static int add_dict_to_tuple(PyObject *tuple, Py_ssize_t index, PyObject *dict)
{
    if (tuple == NULL || dict == NULL) {
        return -1;
    }

    if (!PyTuple_Check(tuple)) {
        return -1;
    }

    if (index < 0 || index >= PyTuple_Size(tuple)) {
        return -1;
    }

    Py_INCREF(dict);

    if (PyTuple_SetItem(tuple, index, dict) != 0) {
        return -1;
    }

    return 0;
}

int main(void)
{
    int exit_status = EXIT_FAILURE;
    PyObject *tuple = NULL;
    PyObject *dict = NULL;
    PyObject *key = NULL;
    PyObject *value = NULL;

    Py_Initialize();

    tuple = PyTuple_New(1);
    if (tuple == NULL) {
        goto cleanup;
    }

    dict = PyDict_New();
    if (dict == NULL) {

    key = PyUnicode_FromString("language");

    if (value == NULL) {

**Analysis notes:**

All the "possible weaknesses" flagged in the original source are false positives from a static analyzer that could not locate `Python.h` on the analysis machine. Every one of them (`unknown type name 'PyObject'`, `unknown type name 'Py_ssize_t'`, and all the implicit-function-declaration warnings for `Py_Initialize`, `PyTuple_New`, `PyDict_New`, `PyUnicode_FromString`, `Py_INCREF`, `Py_XDECREF`, etc.) cascades from that single missing header. Once compiled with the correct flags — `gcc $(python3-config --cflags) app.c $(python3-config --ldflags --embed)` — none of these diagnostics appear.

The code itself is already sound:

- **Reference counting is correct.** `PyTuple_SetItem` *steals* a reference, so the `Py_INCREF(dict)` before it is required (since `main` still holds and later decrefs `dict`). On failure, `PyTuple_SetItem` decrefs the stolen reference itself, so there is no leak on the error path.
- **`PY_SSIZE_T_CLEAN`** is correctly defined before including `Python.h`, as required since Python 3.10.
- **Error handling** uses a single `cleanup` label with `Py_XDECREF` (NULL-safe), checks `PyErr_Occurred()` before printing, and validates `Py_FinalizeEx()`'s return value — all correct practice for an embedded interpreter.
- **Bounds and type checks** in `add_dict_to_tuple` (`PyTuple_Check`, index range validation) guard against misuse.

The only substantive fix retained from the comments is the `__has_include` fallback chain with an explicit `#error`, which converts the analyzer's silent header-resolution failure into a clear, actionable compile-time message.
