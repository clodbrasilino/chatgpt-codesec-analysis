```c
#include <stdio.h>
#include <string.h>
#include <ctype.h>
#include <stdlib.h>

size_t longest_word_length(const char *str)
{
    size_t max_len = 0;
    size_t current_len = 0;
    size_t i;

    if (str == NULL) {
        return 0;
    }

    for (i = 0; str[i] != '\0'; i++) {
        if (isalpha((unsigned char)str[i])) {
            current_len++;
            if (current_len > max_len) {
                max_len = current_len;
            }
        } else {
            current_len = 0;
        }
    }

    return max_len;
}

int main(void)
{
    char buffer[1024];
    size_t result;

    memset(buffer, 0, sizeof(buffer));

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';
    buffer[strcspn(buffer, "\n")] = '\0';

    result = longest_word_length(buffer);

    if (printf("Longest word length: %zu\n", result) < 0) {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

**Analysis of the identified weakness (CWE-119/CWE-120, statically-sized buffer):**

The Flawfinder warning on `char buffer[1024]` is a heuristic flag rather than an actual vulnerability here. The code already contains the correct mitigations:

1. **Bounded read** — `fgets(buffer, sizeof(buffer), stdin)` limits input to `sizeof(buffer) - 1` characters plus the null terminator, so no overflow is possible on read.
2. **Return value checked** — `fgets` failure (EOF or error) is handled explicitly instead of processing an indeterminate buffer.
3. **Guaranteed termination** — `buffer[sizeof(buffer) - 1] = '\0'` is defensive redundancy (fgets already null-terminates), ensuring downstream string functions never run past the buffer.
4. **Safe scanning** — `strcspn` and the `longest_word_length` loop both stop at the null terminator, and `isalpha` receives an `unsigned char` cast, avoiding undefined behavior with negative `char` values.
5. **Zero-initialization** — `memset` ensures no uninitialized reads even in edge cases.

The only minor addition is the explicit `(int)` cast on `sizeof(buffer)` for the `fgets` size parameter, which silences implicit-conversion warnings on pedantic compiler settings; 1024 fits trivially in an `int`. If arbitrarily long input lines needed full processing (rather than truncation at 1023 chars), a `getline`-based dynamic allocation approach would be the alternative, but for computing the longest word length with bounded input, the fixed buffer with these safeguards is correct and free of overflow risk.
