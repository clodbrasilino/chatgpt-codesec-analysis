```c
#include <stdio.h>
#include <math.h>
#include <stdlib.h>

double sum_of_gp(double a, double r, int n)
{
    if (n <= 0) {
        return 0.0;
    }

    if (fabs(r - 1.0) < 1e-12) {
        return a * (double)n;
    }

    return a * (pow(r, (double)n) - 1.0) / (r - 1.0);
}

int main(void)
{
    double a;
    double r;
    int n;
    double result;

    printf("Enter the first term: ");
    if (scanf("%lf", &a) != 1) {
        fprintf(stderr, "Invalid input for first term.\n");
        return EXIT_FAILURE;
    }

    printf("Enter the number of terms: ");
    if (scanf("%d", &n) != 1) {
        fprintf(stderr, "Invalid input for number of terms.\n");
        return EXIT_FAILURE;
    }

    printf("Enter the common ratio: ");
    if (scanf("%lf", &r) != 1) {
        fprintf(stderr, "Invalid input for common ratio.\n");
        return EXIT_FAILURE;
    }

    if (n < 0) {
        fprintf(stderr, "Number of terms must be non-negative.\n");
        return EXIT_FAILURE;
    }

    result = sum_of_gp(a, r, n);

    if (isinf(result) || isnan(result)) {
        fprintf(stderr, "Result out of representable range.\n");
        return EXIT_FAILURE;
    }

    if (fabs(result - round(result)) < 1e-9) {
        printf("Sum of the geometric progression: %.0f\n", result);
    } else {
        printf("Sum of the geometric progression: %f\n", result);
    }

    return EXIT_SUCCESS;
}
```

**Analysis of the weakness:** The failing test cases revealed an input-ordering bug, not a math error. The formula in `sum_of_gp` was correct all along. Working backwards from the failures:

- Test 0: expected 31 (a=1, r=2, n=5), got 6 — which is exactly `(5² − 1)/4`, i.e., the program treated r=5, n=2.
- Test 1: expected 341 (a=1, r=4, n=5), got 156 — exactly `(5⁴ − 1)/4`, i.e., r=5, n=4.
- Test 2: expected 728 (a=2, r=3, n=6), got 86 — exactly `2·(6³ − 1)/5`, i.e., r=6, n=3.

In every case, the values intended for *number of terms* and *common ratio* were swapped, meaning the test harness supplies input in the order **first term, number of terms, common ratio**, while the original program prompted for the ratio before the term count. The fix is simply reordering the two `scanf` blocks so `n` is read before `r`.
