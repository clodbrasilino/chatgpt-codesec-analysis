```c
#include <stdio.h>
#include <ctype.h>
#include <limits.h>

static int get_ascii_value(char c)
{
    return (int)(unsigned char)c;
}

static void flush_stdin(void)
{
    int ch;
    unsigned long guard = 0;

    do {
        ch = getchar();
        guard++;
    } while (ch != '\n' && ch != EOF && guard < ULONG_MAX);
}

int main(void)
{
    int input;

    printf("Enter a character: ");
    if (fflush(stdout) != 0) {
        return 1;
    }

    input = getchar();
    if (input == EOF) {
        fprintf(stderr, "Error: failed to read input.\n");
        return 1;
    }

    if (input != '\n') {
        flush_stdin();
    }

    if (isprint((unsigned char)input)) {
        printf("The ASCII value of '%c' is %d\n", (char)input, get_ascii_value((char)input));
    } else {
        printf("The ASCII value of the entered character is %d\n", get_ascii_value((char)input));
    }

    return 0;
}
```

**Analysis notes:**

The Flawfinder warnings on `getchar()` (CWE-120, CWE-20) are largely false positives in this context, since `getchar()` reads a single character into an `int` and involves no user-controlled buffer. However, the flagged concern about "recursive loops" relates to unbounded loop iteration on attacker-controlled input streams. The rewrite addresses this defensively:

1. **`flush_stdin()` loop bounding** — A `guard` counter caps iterations at `ULONG_MAX`, guaranteeing termination even against a pathological infinite input stream that never delivers `\n` or `EOF`. In practice `EOF` handling already prevents infinite loops on closed streams, but the bound makes the invariant explicit.

2. **`EOF` checked before use** — `input` is stored as `int` (not `char`) so the `EOF` sentinel is distinguishable from valid byte values, and it is validated before any conversion. This is the correct pattern for CWE-20 (improper input validation).

3. **`isprint()` safety** — The argument is cast to `unsigned char` before being passed, avoiding undefined behavior for negative `char` values (required by the C standard for `<ctype.h>` functions).

4. **`fflush(stdout)` return value checked** — Output errors are detected before reading input.

No fixed-size buffers, `gets()`, `scanf("%s")`, or unbounded string copies exist anywhere in the code, so no genuine CWE-120 buffer overflow surface remains.
