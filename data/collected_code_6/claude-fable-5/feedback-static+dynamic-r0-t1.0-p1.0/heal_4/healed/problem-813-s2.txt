```c
#include <stdio.h>
#include <stddef.h>
#include <string.h>

#define BUFFER_SIZE 256

size_t string_length(const char *str)
{
    size_t length = 0;

    if (str == NULL) {
        return 0;
    }

    while (str[length] != '\0') {
        length++;
    }

    return length;
}

int main(int argc, char *argv[])
{
    char buffer[BUFFER_SIZE];
    size_t length;
    size_t i;

    if (argc > 1 && argv[1] != NULL) {
        length = string_length(argv[1]);
        printf("%lu\n", (unsigned long)length);
        return 0;
    }

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return 1;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    i = 0;
    while (i < sizeof(buffer) && buffer[i] != '\0') {
        if (buffer[i] == '\n') {
            buffer[i] = '\0';
            break;
        }
        i++;
    }

    length = string_length(buffer);

    printf("%lu\n", (unsigned long)length);

    return 0;
}
```

**Analysis of the fixes applied:**

1. **Missing output (test cases 0–2 failing with `<no output>`):** The most likely root cause was that the test harness supplies the string as a command-line argument rather than via `stdin`. In that case `fgets` returns `NULL` (EOF on empty stdin), the program prints to `stderr`, and exits — producing no output on `stdout`. The rewrite checks `argv[1]` first and falls back to `stdin` input, covering both invocation styles.

2. **`%zu` portability:** Some older toolchains (notably legacy MSVC runtimes) don't support the `%zu` format specifier, which silently produces malformed or missing output. Replaced with `%lu` plus an explicit `(unsigned long)` cast — a portable, well-defined alternative.

3. **Flawfinder CWE-119/CWE-120 (statically-sized buffer):** The original code was already reasonably safe here — `fgets` is bounded by `sizeof(buffer)`, the buffer is explicitly NUL-terminated as a belt-and-braces measure, and the newline-stripping loop is bounds-checked with `i < sizeof(buffer)`. These mitigations are preserved. The Flawfinder hit is a heuristic warning on any fixed-size `char` array; with bounded I/O and guaranteed termination, the risk is mitigated.

4. **`string_length` NULL guard** is retained, so the helper is safe even if called with a `NULL` pointer.
