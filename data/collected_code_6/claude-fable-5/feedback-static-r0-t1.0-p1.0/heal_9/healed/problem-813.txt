```c
#include <stdio.h>
#include <stdlib.h>

#define MAX_INPUT 256
#define FLUSH_GUARD_MAX 1000000

static size_t string_length(const char *str, size_t max_len)
{
    size_t length = 0;

    if (str == NULL) {
        return 0;
    }

    while (length < max_len && str[length] != '\0') {
        length++;
    }

    return length;
}

static void flush_stdin(void)
{
    int ch;
    size_t guard = 0;

    do {
        ch = getchar();
        guard++;
    } while (ch != '\n' && ch != EOF && guard < FLUSH_GUARD_MAX);
}

int main(void)
{
    char buffer[MAX_INPUT] = {0};
    size_t length;

    printf("Enter a string: ");

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    length = string_length(buffer, sizeof(buffer));

    if (length > 0 && buffer[length - 1] == '\n') {
        buffer[length - 1] = '\0';
        length--;
        printf("You entered: %s\n", buffer);
    } else if (length == sizeof(buffer) - 1) {
        flush_stdin();
        printf("You entered (truncated): %s\n", buffer);
    } else {
        printf("You entered: %s\n", buffer);
    }

    printf("Length of the string: %zu\n", length);

    return EXIT_SUCCESS;
}
```

**Analysis summary:**

The original code is already well-hardened, and the Flawfinder hits are false positives that have been properly mitigated:

1. **`char buffer[MAX_INPUT]` (CWE-119/CWE-120):** The statically-sized array is safe because input is read with `fgets(buffer, (int)sizeof(buffer), stdin)`, which strictly limits the number of bytes written. The explicit `buffer[sizeof(buffer) - 1] = '\0'` is a defensive (technically redundant with `fgets`) guarantee of null-termination. The custom `string_length` also caps traversal at `max_len`, so it never reads past the buffer even if termination failed.

2. **`getchar()` in a loop (CWE-120/CWE-20):** `getchar()` writes to no buffer, so overflow is impossible. The `FLUSH_GUARD_MAX` counter additionally prevents an unbounded loop (e.g., a malicious pipe streaming infinite data without a newline), and the `EOF` check prevents an infinite loop on closed streams.

Other correct practices worth noting: truncation is detected (`length == sizeof(buffer) - 1` with no trailing newline) and the remainder of the line is drained so it doesn't leak into subsequent reads; the return value of `fgets` is checked; `%zu` is correctly used for `size_t`; and `NULL` is handled in `string_length`. No functional or security changes were required — the code stands as written.
