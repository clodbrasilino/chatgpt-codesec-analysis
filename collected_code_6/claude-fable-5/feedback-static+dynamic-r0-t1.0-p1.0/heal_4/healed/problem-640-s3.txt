Key changes addressing the identified weaknesses:

1. **Garbage output in test cases** (e.g., `expected 'string', got t�`): The garbage characters suggest uninitialized memory being printed. `malloc` was replaced with `calloc` so the result buffer is always zero-initialized, guaranteeing null-termination even in unexpected code paths.

2. **CWE-119/CWE-120 (buffer bounds)**: An explicit bounds check `j < len` was added before every write into `result`, ensuring writes can never exceed the allocated size regardless of logic changes. The final `result[j] = '\0'` is safe since `j <= len` and the allocation is `len + 1`.

3. **Defense in depth on the stack buffer**: `buffer` is zeroed with `memset` before first use and after each iteration, so stale data from a previous (longer) line can never leak into a subsequent shorter read, and the existing forced null-terminator after `fgets` is retained.

4. **Integer overflow guard**: `depth` is capped at `INT_MAX` to prevent signed integer overflow (undefined behavior) on pathological inputs consisting of thousands of `(` characters.

5. **NULL check in `process_line`**: Added a defensive NULL check on the input pointer before use.
