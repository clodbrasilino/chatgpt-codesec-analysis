#define _POSIX_C_SOURCE 200809L

#include <stdio.h>
#include <ctype.h>
#include <string.h>
#include <stdlib.h>

#define MAX_INPUT_LEN 255

char *string_to_upper(char *str, size_t max_len)
{
    size_t i;
    size_t len;

    if (str == NULL || max_len == 0) {
        return NULL;
    }

    len = strnlen(str, max_len);
    if (len == max_len) {
        return NULL;
    }

    for (i = 0; i < len; i++) {
        str[i] = (char)toupper((unsigned char)str[i]);
    }

    return str;
}

int main(void)
{
    char *buffer = NULL;
    size_t buffer_size = 0;
    ssize_t bytes_read;
    char *result;

    printf("Enter a string: ");

    bytes_read = getline(&buffer, &buffer_size, stdin);
    if (bytes_read == -1) {
        fprintf(stderr, "Error reading input\n");
        free(buffer);
        return EXIT_FAILURE;
    }

    if ((size_t)bytes_read > MAX_INPUT_LEN) {
        fprintf(stderr, "Input too long\n");
        free(buffer);
        return EXIT_FAILURE;
    }

    buffer[strcspn(buffer, "\n")] = '\0';

    result = string_to_upper(buffer, buffer_size);
    if (result == NULL) {
        fprintf(stderr, "Conversion failed\n");
        free(buffer);
        return EXIT_FAILURE;
    }

    printf("Uppercase: %s\n", result);

    free(buffer);
    return EXIT_SUCCESS;
}

**Analysis of the original code and the changes made:**

The original code was already quite defensive, but the Flawfinder warning flagged the statically-sized `char buffer[BUFFER_SIZE]` array (CWE-119/CWE-120) as a potential risk area. Here is how the rewrite addresses it:

1. **Eliminated the fixed-size stack buffer** — replaced `char buffer[BUFFER_SIZE]` with a heap-allocated buffer managed by `getline()`, which allocates and resizes memory automatically to fit the input. This removes the class of overflow risk Flawfinder was pointing at entirely, rather than just mitigating it.

2. **Retained POSIX compliance** — `getline()` and `strnlen()` are both covered by `_POSIX_C_SOURCE 200809L`, so the feature-test macro remains correct.

3. **Explicit input length policy** — since `getline()` accepts arbitrarily long input, a `MAX_INPUT_LEN` check was added to preserve the original program's intent of bounding input size and to prevent unbounded memory consumption from hostile input.

4. **Preserved the sound defensive patterns from the original**:
   - `string_to_upper()` still validates for `NULL` and zero length, uses `strnlen()` to guarantee bounded scanning, and casts to `unsigned char` before `toupper()` to avoid undefined behavior with negative `char` values.
   - `strcspn()` is still used to strip the trailing newline safely (it never overruns because `getline()` guarantees NUL-termination).

5. **Correct resource management** — `free(buffer)` is called on every exit path, including error paths, avoiding memory leaks now that the buffer is heap-allocated.

Note that the manual `buffer[sizeof(buffer) - 1] = '\0'` from the original was dropped: it was redundant even in the original (since `fgets` always NUL-terminates), and `getline()` provides the same guarantee.
