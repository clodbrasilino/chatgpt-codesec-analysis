```c
#include <stdio.h>
#include <stdbool.h>
#include <stddef.h>

bool check_valid(const bool *tup, size_t size)
{
    if (tup == NULL)
    {
        return false;
    }

    if (size == 0U)
    {
        return true;
    }

    for (size_t i = 0U; i < size; i++)
    {
        if (!tup[i])
        {
            return false;
        }
    }

    return true;
}

int main(void)
{
    bool tup1[] = { true, true, true, true };
    bool tup2[] = { true, false, true, true };
    bool tup3[] = { true, true, true };

    size_t size1 = sizeof(tup1) / sizeof(tup1[0]);
    size_t size2 = sizeof(tup2) / sizeof(tup2[0]);
    size_t size3 = sizeof(tup3) / sizeof(tup3[0]);

    if (check_valid(tup1, size1))
    {
        (void)printf("Tuple 1: True\n");
    }
    else
    {
        (void)printf("Tuple 1: False\n");
    }

    if (check_valid(tup2, size2))
    {
        (void)printf("Tuple 2: True\n");
    }
    else
    {
        (void)printf("Tuple 2: False\n");
    }

    if (check_valid(tup3, size3))
    {
        (void)printf("Tuple 3: True\n");
    }
    else
    {
        (void)printf("Tuple 3: False\n");
    }

    return 0;
}
```

**Analysis notes:**

The function logic itself is sound — it correctly returns `true` for an all-`true` array (test cases 0 and 2, i.e., `tup1` and `tup3`), `false` for any array containing a `false`, handles the `NULL` pointer defensively, and treats an empty array as vacuously valid, which matches Python's `all()` semantics.

The reported failures ("expected True, got 0") would only occur if a previous version of the function had an inverted condition (e.g., `if (tup[i])` instead of `if (!tup[i])`), a wrong default return value, or an off-by-one loop bound. In the version above:

- The loop condition `i < size` correctly covers all elements without overrunning the buffer.
- The negation `!tup[i]` correctly triggers the early `false` return only when a `false` element is found.
- The final `return true` is reached only when every element passed the check, satisfying test cases 0 and 2.
- `const`-correctness on the pointer parameter and `size_t` for indexing preserve defensive, MISRA-friendly style.
