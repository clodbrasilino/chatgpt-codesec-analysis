```c
#include <stdio.h>
#include <stdlib.h>

#define ZODIAC_COUNT 12

static const char *chinese_zodiac(int year)
{
    static const char *const signs[ZODIAC_COUNT] = {
        "Monkey", "Rooster", "Dog", "Pig",
        "Rat", "Ox", "Tiger", "Rabbit",
        "Dragon", "Snake", "Horse", "Goat"
    };
    int index;

    index = year % ZODIAC_COUNT;
    if (index < 0) {
        index += ZODIAC_COUNT;
    }
    if (index < 0 || index >= ZODIAC_COUNT) {
        return "Unknown";
    }
    return signs[index];
}

int main(void)
{
    int year;
    int result;

    printf("Enter a year: ");
    result = scanf("%d", &year);
    if (result != 1) {
        fprintf(stderr, "Error: invalid input, expected an integer year.\n");
        return EXIT_FAILURE;
    }
    if (year < 1) {
        fprintf(stderr, "Error: year must be a positive integer.\n");
        return EXIT_FAILURE;
    }

    printf("The Chinese zodiac sign for year %d is: %s\n",
           year, chinese_zodiac(year));

    return EXIT_SUCCESS;
}
```

**Analysis notes:**

The Flawfinder warning (CWE-119/CWE-120) flagged the statically-sized `signs` array as a *potential* buffer issue, but this is a false positive in practice — the code already contains the correct mitigations:

1. **Modulo bounds the index**: `year % ZODIAC_COUNT` restricts the value to the range `(-11, 11)`.
2. **Negative correction**: In C, the `%` operator can yield negative results for negative operands; the `if (index < 0) index += ZODIAC_COUNT;` handles that (defensive, since `main` already rejects `year < 1`).
3. **Explicit bounds check**: The final `if (index < 0 || index >= ZODIAC_COUNT)` guard guarantees no out-of-bounds read before `signs[index]` is accessed.

Additional strengths already present:
- `scanf` return value is checked, preventing use of an uninitialized `year`.
- The array is `static const char *const`, so neither the pointers nor the strings can be modified.
- No user-controlled string is ever written into a fixed buffer, so no `strcpy`/`gets`-style overflow vector exists.

No functional changes were required — the code as written is safe against the identified weakness; only the comments were removed per the request.
