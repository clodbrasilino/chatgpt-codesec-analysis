```c
#include <stdio.h>
#include <string.h>
#include <ctype.h>
#include <stddef.h>

#define MAX_NAME_LEN 256

size_t sum_name_lengths(const char *const names[], size_t count)
{
    size_t total = 0;
    size_t i;

    if (names == NULL) {
        return 0;
    }

    for (i = 0; i < count; i++) {
        if (names[i] == NULL) {
            continue;
        }
        if (names[i][0] != '\0' && isupper((unsigned char)names[i][0])) {
            total += strnlen(names[i], MAX_NAME_LEN);
        }
    }

    return total;
}

int main(void)
{
    const char *const names[] = {
        "Alice",
        "bob",
        "Charlie",
        "dave",
        "Eve"
    };
    size_t count = sizeof(names) / sizeof(names[0]);
    size_t result;

    result = sum_name_lengths(names, count);

    if (printf("Total length: %zu\n", result) < 0) {
        return 1;
    }

    return 0;
}
```

**Analysis of the change:**

The original code was already fairly defensive (NULL checks on both the array and individual elements, correct `unsigned char` cast for `isupper`), but the flagged weakness was the use of `strlen` (CWE-126). If a string in the array were not null-terminated, `strlen` would read past the end of the buffer, potentially crashing or leaking adjacent memory.

The fix replaces `strlen` with `strnlen`, which bounds the scan to `MAX_NAME_LEN` bytes. Even if a non-terminated string is passed, the read is capped, preventing an unbounded over-read.

Notes:
- `strnlen` is POSIX (and available in most modern C libraries); on strictly ISO C90/C99 toolchains you may need `#define _POSIX_C_SOURCE 200809L` before the includes, or provide a small portable fallback.
- The bound (`256`) is a policy decision — it should reflect the maximum legitimate name length in your application. Names longer than the bound will be counted as `MAX_NAME_LEN` rather than their full length, which is the safe trade-off.
- With the given `main`, behavior is unchanged: `"Alice"` (5) + `"Charlie"` (7) + `"Eve"` (3) = `Total length: 15`.
