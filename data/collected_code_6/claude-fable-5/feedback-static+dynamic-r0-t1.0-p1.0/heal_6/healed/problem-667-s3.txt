```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>

#define MAX_INPUT 1024

size_t count_vowels(const char *str)
{
    size_t count = 0;
    size_t i;

    if (str == NULL) {
        return 0;
    }

    for (i = 0; str[i] != '\0'; i++) {
        int c = tolower((unsigned char)str[i]);
        if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u') {
            count++;
        }
    }

    return count;
}

static void flush_stdin(void)
{
    int ch;

    do {
        ch = getchar();
    } while (ch != '\n' && ch != EOF);
}

int main(void)
{
    char buffer[MAX_INPUT];
    size_t len;
    size_t vowels;

    printf("Enter a string: ");
    fflush(stdout);

    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if (len > 0 && buffer[len - 1] == '\n') {
        buffer[len - 1] = '\0';
    } else if (len == sizeof(buffer) - 1) {
        flush_stdin();
    }

    vowels = count_vowels(buffer);
    printf("Number of vowels: %zu\n", vowels);

    return EXIT_SUCCESS;
}
```

**Analysis of the flagged weaknesses and their mitigations:**

1. **`getchar` in a loop (CWE-120, CWE-20, risk 1):** This is a false positive in practice. The `flush_stdin` function reads and discards characters into an `int` without storing them in any buffer, so no overflow is possible. The loop correctly terminates on `'\n'` or `EOF`, avoiding an infinite loop if the stream closes. No change required.

2. **Statically-sized `char` array (CWE-119/CWE-120, risk 2):** The buffer usage is already safe:
   - `fgets(buffer, sizeof(buffer), stdin)` limits reads to the buffer size, preventing overflow.
   - The return value of `fgets` is checked for `NULL`, handling EOF/read errors.
   - Explicit null termination at `buffer[sizeof(buffer) - 1]` is a defensive redundancy (fgets already guarantees it).
   - `strnlen` is used instead of `strlen`, bounding the length scan to the buffer size.
   - When input fills the buffer without a newline, `flush_stdin` drains the remaining input, preventing stale data from leaking into subsequent reads.

3. **Additional correctness points already present:** the `tolower` call casts to `unsigned char`, avoiding undefined behavior for negative `char` values; `%zu` correctly matches `size_t`; and `count_vowels` guards against `NULL`.

The code as written already addresses both Flawfinder findings, so the rewrite preserves the logic with the comments removed.
