```c
#include <stdio.h>
#include <stdlib.h>

static int count_rotations(const int *arr, size_t n)
{
    size_t low;
    size_t high;

    if (arr == NULL || n == 0U) {
        return -1;
    }

    low = 0U;
    high = n - 1U;

    while (low < high) {
        size_t mid = low + ((high - low) / 2U);

        if (arr[mid] > arr[high]) {
            low = mid + 1U;
        } else {
            high = mid;
        }
    }

    return (int)low;
}

int main(void)
{
    int arr[] = {15, 18, 2, 3, 6, 12};
    size_t n = sizeof(arr) / sizeof(arr[0]);
    int rotations;

    rotations = count_rotations(arr, n);

    if (rotations < 0) {
        if (fprintf(stderr, "Invalid input array\n") < 0) {
            return EXIT_FAILURE;
        }
        return EXIT_FAILURE;
    }

    if (printf("Number of rotations: %d\n", rotations) < 0) {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

**Analysis of the fix:**

The original code's bug was in the return statement: `return (int)((n - low) % n);`

The binary search itself was correct — it finds `low` as the index of the minimum element, which by convention *is* the number of rotations of an ascending sorted array. The transformation `(n - low) % n` inverted the result, which explains both test failures:

- **Test case 0**: expected `1`, got `2` — consistent with `n = 3`, `low = 1`, where `(3 - 1) % 3 = 2` but the correct answer is `low = 1`.
- **Test case 2**: expected `3`, got `1` — consistent with `n = 4`, `low = 3`, where `(4 - 3) % 4 = 1` but the correct answer is `low = 3`.

Returning `low` directly resolves both failures. For the array in `main` (`{15, 18, 2, 3, 6, 12}`), the program now correctly prints `Number of rotations: 2`, since the minimum element `2` sits at index 2.

The rest of the code is sound: NULL/empty-array guards, overflow-safe midpoint calculation (`low + (high - low) / 2`), checked I/O return values, and proper use of `size_t` for indices.
