```c
#include <stdio.h>
#include <stdlib.h>

unsigned int set_rightmost_unset_bit(unsigned int n)
{
    if (n != 0U && (n & (n + 1U)) == 0U)
    {
        return n;
    }
    return n | (n + 1U);
}

int main(void)
{
    unsigned int values[] = { 0U, 10U, 15U, 21U, ~0U };
    size_t count = sizeof(values) / sizeof(values[0]);
    size_t i;

    for (i = 0; i < count; i++)
    {
        unsigned int result = set_rightmost_unset_bit(values[i]);
        if (printf("Input: %u -> Output: %u\n", values[i], result) < 0)
        {
            return EXIT_FAILURE;
        }
    }

    return EXIT_SUCCESS;
}
```

**Analysis of the fix:**

The original code only special-cased `~0U` (all bits set), but the failing test case revealed the actual intent: numbers whose set bits form a contiguous block from bit 0 upward (like `15` = `0b1111`) should be returned unchanged, since they have no unset bit *within* their significant bits.

- **Original behavior:** `set_rightmost_unset_bit(15)` returned `15 | 16 = 31`, extending the number by setting a bit above the most significant set bit — hence "expected 15, got 31".
- **Fix:** The condition `(n & (n + 1U)) == 0U` detects any value of the form `2^k - 1` (e.g., `1`, `3`, `7`, `15`, ..., `~0U`), covering the old `~0U` check as well.
- **Edge case preserved:** The `n != 0U` guard keeps the behavior for input `0` returning `1` (since `0 & 1 == 0` would otherwise incorrectly short-circuit), matching the originally passing test case 0.

Verified outputs: `0 → 1`, `10 → 11`, `15 → 15`, `21 → 23`, `~0U → ~0U`.
