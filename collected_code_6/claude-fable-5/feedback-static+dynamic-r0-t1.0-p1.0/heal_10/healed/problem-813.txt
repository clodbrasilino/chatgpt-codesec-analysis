#include <stdio.h>
#include <stdlib.h>

#define MAX_INPUT 256

size_t string_length(const char *str)
{
    size_t length = 0;

    if (str == NULL) {
        return 0;
    }

    while (str[length] != '\0') {
        length++;
    }

    return length;
}

int main(int argc, char *argv[])
{
    char buffer[MAX_INPUT];
    size_t length;
    size_t i;

    buffer[0] = '\0';

    if (argc > 1 && argv[1] != NULL) {
        for (i = 0; i < sizeof(buffer) - 1 && argv[1][i] != '\0'; i++) {
            buffer[i] = argv[1][i];
        }
        buffer[i] = '\0';
    } else {
        if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
            printf("0\n");
            fflush(stdout);
            return EXIT_SUCCESS;
        }
        buffer[sizeof(buffer) - 1] = '\0';
    }

    for (i = 0; i < sizeof(buffer) && buffer[i] != '\0'; i++) {
        if (buffer[i] == '\n' || buffer[i] == '\r') {
            buffer[i] = '\0';
            break;
        }
    }

    length = string_length(buffer);

    printf("%zu\n", length);
    fflush(stdout);

    return EXIT_SUCCESS;
}

**Analysis:**

The original code is already well-defended against the Flawfinder warning, which is a heuristic flag on any statically-sized `char` array rather than an actual detected vulnerability. Here's why the code is safe as written:

1. **Bounded copy from `argv[1]`**: The loop condition `i < sizeof(buffer) - 1` guarantees the copy never exceeds 255 bytes, always leaving room for the null terminator, which is explicitly written at `buffer[i]` after the loop.

2. **Safe stdin read**: `fgets` is used with `sizeof(buffer)`, which inherently limits input to the buffer size including the terminator. The defensive `buffer[sizeof(buffer) - 1] = '\0'` is redundant (fgets always null-terminates on success) but harmless.

3. **Bounded newline strip**: The trimming loop checks `i < sizeof(buffer)` in addition to the null check, so even a hypothetically unterminated buffer wouldn't cause an out-of-bounds read.

4. **NULL-safe helper**: `string_length` guards against a NULL pointer, and `buffer[0] = '\0'` initializes the array before any use.

5. **Correct format specifier**: `%zu` is the proper specifier for `size_t`.

No functional changes were required — the Flawfinder hit (CWE-119/CWE-120, risk level 2) is a false positive here because all writes and reads into `buffer` are explicitly bounds-checked. The rewrite preserves the safe logic with the comments removed as requested.
