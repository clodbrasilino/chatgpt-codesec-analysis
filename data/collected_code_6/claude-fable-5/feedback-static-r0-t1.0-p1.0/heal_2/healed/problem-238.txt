```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

#define BUFFER_SIZE 1024

static unsigned long long count_substrings(const char *str, size_t max_len)
{
    unsigned long long n;

    if (str == NULL)
    {
        return 0ULL;
    }

    n = (unsigned long long)strnlen(str, max_len);
    return (n * (n + 1ULL)) / 2ULL;
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    unsigned long long result;
    size_t len;

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL)
    {
        fprintf(stderr, "Error: failed to read input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if (len > 0 && buffer[len - 1] == '\n')
    {
        buffer[len - 1] = '\0';
    }

    result = count_substrings(buffer, sizeof(buffer));

    if (printf("%llu\n", result) < 0)
    {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

**Analysis of the original code and the flagged weakness:**

The Flawfinder warning (CWE-119/CWE-120) flags `char buffer[BUFFER_SIZE]` as a statically-sized array that could be improperly restricted. This is a heuristic, low-risk (risk 2) finding — it flags the *pattern*, not an actual proven vulnerability. Reviewing the code, the weakness is already fully mitigated:

1. **Bounded input:** `fgets(buffer, (int)sizeof(buffer), stdin)` reads at most `sizeof(buffer) - 1` bytes and always null-terminates on success, so no overflow can occur during input.

2. **Defensive termination:** `buffer[sizeof(buffer) - 1] = '\0';` is a belt-and-suspenders guarantee that the buffer is null-terminated even if some non-conforming `fgets` implementation misbehaved.

3. **Length-limited string operations:** `strnlen(buffer, sizeof(buffer))` is used instead of `strlen`, so even an unterminated buffer could never cause an out-of-bounds read. The same bound is propagated into `count_substrings`.

4. **NULL check:** `count_substrings` guards against a NULL pointer before dereferencing.

5. **Overflow-aware arithmetic:** The substring count `n*(n+1)/2` is computed in `unsigned long long`; with `n ≤ 1023`, the maximum intermediate value (~524,800) is nowhere near overflow.

6. **Error handling:** Both `fgets` and `printf` return values are checked, and failure paths exit with `EXIT_FAILURE`.

Since the code already applies bounds checking and length-limiting functions exactly as the warning recommends, no functional changes are required — the rewrite simply removes the audit comments while preserving the hardened implementation.
