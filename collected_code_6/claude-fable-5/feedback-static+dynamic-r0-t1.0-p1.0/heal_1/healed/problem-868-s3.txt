```c
#include <stdio.h>
#include <string.h>
#include <ctype.h>

#define MAX_INPUT_LEN 4096U

size_t length_of_last_word(const char *s)
{
    size_t len;
    size_t end;
    size_t count;

    if (s == NULL) {
        return 0U;
    }

    len = strnlen(s, MAX_INPUT_LEN);
    if (len == 0U) {
        return 0U;
    }

    end = len;
    while (end > 0U && isspace((unsigned char)s[end - 1U])) {
        end--;
    }

    count = 0U;
    while (end > 0U && !isspace((unsigned char)s[end - 1U])) {
        count++;
        end--;
    }

    return count;
}

int main(void)
{
    const char *tests[] = {
        "Hello World",
        "   fly me   to   the moon  ",
        "luffy is still joyboy",
        "",
        "     ",
        "single"
    };
    size_t num_tests = sizeof(tests) / sizeof(tests[0]);
    size_t i;

    for (i = 0U; i < num_tests; i++) {
        size_t result = length_of_last_word(tests[i]);
        if (printf("Input: \"%s\" -> Last word length: %zu\n", tests[i], result) < 0) {
            return 1;
        }
    }

    return 0;
}
```

**Analysis summary:**

The original code was already quite robust — it guarded against `NULL`, used `(unsigned char)` casts before `isspace()` (avoiding undefined behavior with negative `char` values), and used unsigned index arithmetic carefully to avoid underflow.

The one flagged weakness was the Flawfinder warning on `strlen` (CWE-126, buffer over-read): if a caller passes a buffer that isn't NUL-terminated, `strlen` reads past its end. The fix replaces `strlen` with `strnlen` bounded by `MAX_INPUT_LEN`, guaranteeing the scan terminates within a defined limit even for malformed input. `strnlen` is POSIX (and available on all mainstream platforms); if strict C90/C99 portability were required, an equivalent bounded loop could be substituted.

All other logic — trailing-whitespace trimming and last-word counting — is preserved unchanged, since it was already safe: both loops check `end > 0U` before indexing `s[end - 1U]`, so no out-of-bounds access is possible there.
