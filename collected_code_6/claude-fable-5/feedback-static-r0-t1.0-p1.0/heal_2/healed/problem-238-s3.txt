```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

#define MAX_INPUT_SIZE 1024

unsigned long long count_substrings(const char *str, size_t max_len)
{
    size_t len;

    if (str == NULL) {
        return 0ULL;
    }

    len = strnlen(str, max_len);

    return ((unsigned long long)len * (unsigned long long)(len + 1U)) / 2ULL;
}

int main(void)
{
    char buffer[MAX_INPUT_SIZE];
    char *newline;
    unsigned long long result;

    printf("Enter a string: ");

    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error: failed to read input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    newline = strchr(buffer, '\n');
    if (newline != NULL) {
        *newline = '\0';
    } else {
        int ch;
        while ((ch = getchar()) != '\n' && ch != EOF) {
        }
    }

    result = count_substrings(buffer, sizeof(buffer));

    printf("Number of non-empty substrings: %llu\n", result);

    return EXIT_SUCCESS;
}
```

**Summary of changes made:**

1. **Variable scope (`variableScope` warning):** Moved the declaration of `ch` from function scope into the `else` block, which is the only place it is used. This addresses the cppcheck-style warning and limits the variable's lifetime to where it is needed.

2. **Statically-sized buffer (CWE-119/CWE-120):** The existing mitigations are correct and retained — `fgets(buffer, sizeof(buffer), stdin)` bounds all reads to the buffer size, the explicit NUL terminator at `buffer[sizeof(buffer) - 1]` guarantees termination, and `strnlen(str, max_len)` in `count_substrings` never reads past the buffer even if termination were somehow missing. No overflow is possible.

3. **`getchar` loop (CWE-120/CWE-20):** The loop only discards excess input until newline or EOF and never writes into any buffer, so it cannot overflow. It correctly checks for `EOF` to avoid an infinite loop on closed input. This is a false positive from the static analyzer, and the code is retained as-is.

4. **Comments removed** as requested; the code is otherwise functionally identical and safe against integer overflow in `count_substrings` since the arithmetic is performed in `unsigned long long` (a 1023-character maximum yields at most 523,776, well within range).
