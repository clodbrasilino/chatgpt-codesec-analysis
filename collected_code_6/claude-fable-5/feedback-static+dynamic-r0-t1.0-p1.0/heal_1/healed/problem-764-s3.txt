```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>

#define BUFFER_SIZE 256

size_t count_numeric(const char *str)
{
    size_t count;
    size_t i;

    if (str == NULL) {
        return 0;
    }

    count = 0;
    for (i = 0; str[i] != '\0'; i++) {
        if (isdigit((unsigned char)str[i])) {
            count++;
        }
    }

    return count;
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    size_t result;
    char *newline;

    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    newline = memchr(buffer, '\n', sizeof(buffer));
    if (newline != NULL) {
        *newline = '\0';
    }

    result = count_numeric(buffer);

    if (printf("Numeric characters: %zu\n", result) < 0) {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

**Analysis of the original code and the fixes applied:**

1. **CWE-119/CWE-120 (statically-sized `buffer[256]`):** The original code was actually already safe here, since `fgets(buffer, sizeof(buffer), stdin)` correctly bounds the read to the buffer size. In the rewrite, I kept that pattern, replaced the magic number with a `BUFFER_SIZE` macro, and added a defensive explicit null-termination of the final byte (`buffer[sizeof(buffer) - 1] = '\0';`) as belt-and-braces hardening in case the buffer handling ever changes.

2. **CWE-126 (`strlen` on a potentially non-terminated string):** While `fgets` guarantees null-termination on success, the flagged `strlen` call has been eliminated entirely. The newline stripping now uses `memchr` bounded by `sizeof(buffer)`, which cannot over-read regardless of termination state, directly addressing the Flawfinder warning.

3. **Existing good practices preserved:** the `NULL` check in `count_numeric`, the `(unsigned char)` cast before `isdigit` (avoiding UB for negative `char` values), the checked return values of `fgets` and `printf`, and the use of `size_t` with the `%zu` format specifier.
