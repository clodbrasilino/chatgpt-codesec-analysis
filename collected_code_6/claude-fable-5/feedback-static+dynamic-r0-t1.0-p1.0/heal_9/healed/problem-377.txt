```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define BUFFER_SIZE 256

void remove_char(char *str, char ch)
{
    size_t i;
    size_t j;

    if (str == NULL) {
        return;
    }

    j = 0;
    for (i = 0; str[i] != '\0'; i++) {
        if (str[i] != ch) {
            str[j] = str[i];
            j++;
        }
    }
    str[j] = '\0';
}

static void flush_stdin(void)
{
    int discard;

    do {
        discard = getchar();
    } while (discard != '\n' && discard != EOF);
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    char target;
    int input;

    printf("Enter a string: ");
    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading string input\n");
        return EXIT_FAILURE;
    }
    buffer[sizeof(buffer) - 1] = '\0';

    if (strchr(buffer, '\n') == NULL) {
        flush_stdin();
    }

    buffer[strcspn(buffer, "\n")] = '\0';

    printf("Enter the character to remove: ");
    input = getchar();
    if (input == EOF) {
        fprintf(stderr, "Error reading character input\n");
        return EXIT_FAILURE;
    }
    target = (char)input;

    if (input != '\n') {
        flush_stdin();
    }

    remove_char(buffer, target);

    printf("Result: %s\n", buffer);

    return EXIT_SUCCESS;
}
```

**Analysis of the flagged weaknesses and how the code addresses them:**

1. **`char buffer[BUFFER_SIZE]` (CWE-119/CWE-120, statically-sized array):** This is mitigated correctly. The code uses `fgets(buffer, (int)sizeof(buffer), stdin)`, which limits input to the buffer size, and adds a defensive `buffer[sizeof(buffer) - 1] = '\0'` to guarantee null-termination. No unbounded functions like `gets()` or `strcpy()` are used, so no overflow is possible.

2. **`getchar()` in a loop inside `flush_stdin()` (CWE-120/CWE-20):** This is a false positive in context. The characters read are discarded into a single `int` variable — nothing is written to a buffer, so no boundary can be violated. The loop correctly terminates on both `'\n'` and `EOF`, avoiding an infinite loop on closed input streams.

3. **`getchar()` for the target character (CWE-120/CWE-20):** Also safe as written. The return value is stored in an `int` (not a `char`), which is essential for correctly detecting `EOF`, and the `EOF` case is explicitly handled before the cast to `char`.

Additional robustness already present that's worth noting: the `strchr(buffer, '\n') == NULL` check detects truncated input and drains the remaining characters from `stdin`, preventing leftover input from corrupting the subsequent `getchar()` read — a common bug in this pattern. The `strcspn` idiom safely strips the trailing newline without risking an out-of-bounds access on an empty string. The Flawfinder hits are informational (risk levels 1–2), and no actual code changes were required beyond confirming the existing mitigations.
