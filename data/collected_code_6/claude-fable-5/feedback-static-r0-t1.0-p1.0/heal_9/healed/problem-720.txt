static int add_dict_to_tuple(PyObject *tuple, Py_ssize_t index, PyObject *dict)
{
    if (tuple == NULL || dict == NULL) {
        return -1;
    }

    if (!PyTuple_Check(tuple)) {
        return -1;
    }

    if (index < 0 || index >= PyTuple_Size(tuple)) {
        return -1;
    }

    Py_INCREF(dict);

    if (PyTuple_SetItem(tuple, index, dict) != 0) {
        return -1;
    }

    return 0;
}

    PyObject *dict = NULL;

Analysis notes: all the "possible weaknesses" flagged in the original (unknown type `PyObject`, implicit function declarations, int-to-pointer conversions) stem from a single root cause — the analysis was performed without `<Python.h>` being resolvable. Once the header is properly included, every one of those diagnostics disappears, since `PyObject`, `Py_ssize_t`, and all the C API functions are declared there. The code itself is semantically sound:

- **Reference counting is correct**: `PyTuple_SetItem` steals a reference, so the `Py_INCREF(dict)` before it preserves `main`'s ownership, and the final `Py_XDECREF(dict)` balances correctly. On `PyTuple_SetItem` failure, the stolen reference is consumed anyway, so no leak occurs.
- **Bounds and type checks** guard `add_dict_to_tuple` against NULL, non-tuple inputs, and out-of-range indices.
- **`PY_SSIZE_T_CLEAN`** is defined before the include, as required by modern CPython.
- **Cleanup path** uses `Py_XDECREF` (NULL-safe), reports pending exceptions, and checks `Py_FinalizeEx()` for failure.
