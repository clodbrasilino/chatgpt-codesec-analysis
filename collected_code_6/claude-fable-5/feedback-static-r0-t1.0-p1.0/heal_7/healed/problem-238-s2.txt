#include <stdio.h>
#include <string.h>

#define BUFFER_SIZE 1024U

unsigned long long count_substrings(const char *str, size_t max_len)
{
    unsigned long long n;

    if (str == NULL)
    {
        return 0ULL;
    }

    n = (unsigned long long)strnlen(str, max_len);

    return (n * (n + 1ULL)) / 2ULL;
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    unsigned long long result;
    size_t len;

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL)
    {
        fprintf(stderr, "Error reading input\n");
        return 1;
    }

    buffer[sizeof(buffer) - 1U] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if (len > 0U && buffer[len - 1U] == '\n')
    {
        buffer[len - 1U] = '\0';
    }

    result = count_substrings(buffer, sizeof(buffer));

    if (printf("%llu\n", result) < 0)
    {
        return 1;
    }

    return 0;
}

**Analysis summary:**

The original code was already well-hardened, and the rewritten version preserves those mitigations for the flagged CWE-119/CWE-120 weakness on the statically-sized `buffer`:

1. **Bounded input reading** — `fgets(buffer, (int)sizeof(buffer), stdin)` limits the read to the buffer size, preventing the classic `gets()`-style overflow. Its return value is checked to handle EOF/read errors.

2. **Guaranteed NUL termination** — `buffer[sizeof(buffer) - 1U] = '\0';` is defensive; while `fgets` always NUL-terminates on success, this makes termination explicit and robust against future refactoring.

3. **Length-limited string operations** — `strnlen(buffer, sizeof(buffer))` is used instead of `strlen`, bounding the scan to the buffer size so it can never run past the array even if termination were somehow lost.

4. **Safe newline stripping** — the `len > 0U` check before accessing `buffer[len - 1U]` prevents an out-of-bounds read on an empty string.

5. **Defensive API design** — `count_substrings` takes an explicit `max_len` parameter, checks for `NULL`, and performs its arithmetic in `unsigned long long` (max `n` = 1023, so `n*(n+1)/2` cannot overflow a 64-bit type).

No functional changes were required — the Flawfinder hit is a low-risk (level 2) informational warning triggered simply by the presence of a fixed-size array, and all recommended mitigations (bounds checking, length-limited functions) are already in place.
