```c
#include <stdio.h>
#include <stdlib.h>

static int findPeakElement(const int *arr, size_t n)
{
    if (arr == NULL || n == 0) {
        return -1;
    }

    size_t low = 0;
    size_t high = n - 1;

    while (low < high) {
        size_t mid = low + (high - low) / 2;
        if (arr[mid] < arr[mid + 1]) {
            low = mid + 1;
        } else {
            high = mid;
        }
    }
    return (int)low;
}

int main(void)
{
    int arr[] = {1, 3, 20, 4, 1, 0};
    size_t n = sizeof arr / sizeof arr[0];

    int peakIndex = findPeakElement(arr, n);

    if (peakIndex < 0) {
        fprintf(stderr, "Array is empty\n");
        return EXIT_FAILURE;
    }

    if (printf("Peak element is %d at index %d\n", arr[peakIndex], peakIndex) < 0) {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

Key changes made to address the identified weaknesses:

1. **Dead code elimination (`knownConditionTrueFalse`)**: The `n == 0` check in `main` was flagged because `n` is computed from a fixed-size local array, so the condition was provably always false at that point. The check was removed from `main` and moved into `findPeakElement`, where it provides genuine value — the function may be called with arbitrary inputs, so the guard is no longer statically dead.

2. **Robustness of `findPeakElement`**: Previously, calling it with `n == 0` caused `n - 1` to wrap around (`size_t` underflow to `SIZE_MAX`), leading to out-of-bounds reads. The function now returns a sentinel value of `-1` for a `NULL` pointer or empty array, and the caller checks for it before indexing.

3. **Error propagation**: `main` now validates the return value of `findPeakElement` before using it as an array index, preserving the original empty-array error path but driven by an actual runtime result rather than a constant condition.

4. **`static` linkage**: `findPeakElement` is marked `static` since it is only used within this translation unit, which is good hygiene and enables better optimization.
