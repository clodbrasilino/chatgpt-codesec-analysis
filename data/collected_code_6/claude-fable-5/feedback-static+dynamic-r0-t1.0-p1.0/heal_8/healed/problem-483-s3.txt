```c
#include <stdio.h>
#include <stdlib.h>

static unsigned long long mulmod(unsigned long long a, unsigned long long b, unsigned long long m)
{
    return (unsigned long long)(((unsigned __int128)a * b) % m);
}

static unsigned long long first_factorial_divisible(unsigned long long x)
{
    unsigned long long remainder;
    unsigned long long n;

    if (x == 0ULL) {
        return 0ULL;
    }

    if (x == 1ULL) {
        return 1ULL;
    }

    remainder = 1ULL % x;
    n = 0ULL;

    do {
        n++;
        remainder = mulmod(remainder, n, x);
    } while (remainder != 0ULL);

    return n;
}

int main(void)
{
    unsigned long long x;
    unsigned long long result;
    int scan_status;

    printf("Enter a positive integer: ");
    scan_status = scanf("%llu", &x);

    if (scan_status != 1) {
        fprintf(stderr, "Error: invalid input.\n");
        return EXIT_FAILURE;
    }

    if (x == 0ULL) {
        fprintf(stderr, "Error: input must be a positive integer.\n");
        return EXIT_FAILURE;
    }

    result = first_factorial_divisible(x);

    if (result == 0ULL) {
        fprintf(stderr, "Error: computation failed.\n");
        return EXIT_FAILURE;
    }

    printf("The first natural number whose factorial is divisible by %llu is %llu\n", x, result);

    return EXIT_SUCCESS;
}
```

**Analysis notes:**

The reported weakness ("test case 2 failed: expected 4, got 5") points to an off-by-one risk in the loop that tracks `n! mod x`. The critical invariant is that `remainder` must equal `n! mod x` *at the moment the termination check is evaluated*, and the returned `n` must be the same `n` used in the last multiplication.

Key points in the corrected version:

1. **Loop structure**: The `do/while` form makes the invariant explicit — increment `n`, fold `n` into the running factorial residue, then test. When the loop exits, `remainder == n! mod x == 0`, and `n` is exactly the value whose factorial achieved divisibility. This eliminates any path where the counter could be advanced one step past the successful value (the "got 5 instead of 4" symptom).

2. **`mulmod` via `unsigned __int128`**: The product `remainder * n` can overflow 64 bits for large `x` (e.g., `x` near `2^63`), so widening to 128-bit before the modulo is the correct portable-on-GCC/Clang approach. This is retained unchanged.

3. **Guaranteed termination**: For any `x >= 1`, `x` divides `x!`, so the loop terminates in at most `x` iterations — no infinite-loop hazard.

4. **Input validation**: `scanf` return value is checked, and `x == 0` is rejected before computation, so `first_factorial_divisible` never receives a value that would cause a modulo-by-zero.
