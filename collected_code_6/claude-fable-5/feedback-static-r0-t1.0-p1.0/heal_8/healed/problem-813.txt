```c
#include <stdio.h>
#include <stdlib.h>

#define MAX_INPUT 256
#define FLUSH_GUARD_MAX 1000000

static size_t string_length(const char *str, size_t max_len)
{
    size_t length = 0;

    if (str == NULL) {
        return 0;
    }

    while (length < max_len && str[length] != '\0') {
        length++;
    }

    return length;
}

static void flush_stdin(void)
{
    int ch;
    size_t guard = 0;

    do {
        ch = getchar();
        guard++;
    } while (ch != '\n' && ch != EOF && guard < FLUSH_GUARD_MAX);
}

int main(void)
{
    char buffer[MAX_INPUT] = {0};
    size_t length;

    printf("Enter a string: ");

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    length = string_length(buffer, sizeof(buffer));

    if (length > 0 && buffer[length - 1] == '\n') {
        buffer[length - 1] = '\0';
        length--;
        printf("You entered: %s\n", buffer);
    } else if (length == sizeof(buffer) - 1) {
        flush_stdin();
        printf("You entered (truncated): %s\n", buffer);
    } else {
        printf("You entered: %s\n", buffer);
    }

    printf("Length of the string: %zu\n", length);

    return EXIT_SUCCESS;
}
```

**Analysis of the identified weaknesses and why this code is already safe:**

1. **`getchar()` in a loop (CWE-120, CWE-20):** This warning is a false positive in practice here. `getchar()` returns an `int` and writes to no buffer, so there is no overflow risk. The `guard` counter (`FLUSH_GUARD_MAX`) additionally bounds the loop, preventing an infinite loop on a pathological stream that never yields `'\n'` or `EOF`. The loop also correctly checks for `EOF`, using `int ch` (not `char`), which is essential for reliable `EOF` detection.

2. **Statically-sized `char` array (CWE-119/CWE-120):** The buffer is used safely:
   - Input is read exclusively with `fgets(buffer, (int)sizeof(buffer), stdin)`, which enforces the bound and always null-terminates within the given size.
   - A defensive `buffer[sizeof(buffer) - 1] = '\0';` guarantees termination even if the stream behaves unexpectedly.
   - `string_length()` is a bounded replacement for `strlen()`, never reading past `max_len`, and handles `NULL` gracefully.
   - The truncation case (`length == sizeof(buffer) - 1` with no trailing newline) is detected, the remaining stdin is drained via `flush_stdin()`, and the user is informed the input was truncated — preventing leftover input from corrupting subsequent reads.
   - The `fgets()` return value is checked, handling `EOF`/read errors explicitly.

The code as written already mitigates both flagged issues; the rewrite above preserves those mitigations while removing comments and hoisting the guard limit to a named constant.
