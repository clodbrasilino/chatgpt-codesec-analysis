**Analysis of the original code and the fixes applied:**

1. **`strnlen` portability (root cause of the failing test cases):** `strnlen` is a POSIX function, not part of strict ISO C90/C99. On toolchains or test harnesses compiling in strict standard mode, the code fails to build or link — which explains why all three test cases produced *no output at all* rather than incorrect output. The logic of the conversion itself was correct (`GoogleAssistant` → `google_assistant` works as written). The rewrite replaces `strnlen` with a bounded manual scan, guaranteeing portability while retaining the over-read protection (CWE-126).

2. **CWE-119/CWE-120 (statically-sized buffer):** The Flawfinder hit on `char buffer[MAX_INPUT_LEN]` is mitigated by: passing `sizeof(buffer)` to `fgets` (which always NUL-terminates within bounds), zero-initializing the buffer with `memset`, and defensively forcing a NUL terminator at the last index.

3. **CWE-126 (`strlen` on possibly unterminated string):** Replaced `strlen` in `main` with a bounded scan capped at `sizeof(buffer)`, so even a hypothetically unterminated buffer cannot be over-read.

4. **Retained defensive properties:** overflow-checked capacity computation (`SIZE_MAX` guard before `input_len * 2 + 1`), bounds checks before every write, cleanup of allocated memory on all failure paths, `unsigned char` casts before `isupper`/`tolower` (avoiding UB for negative `char` values), and checked return values for `fgets` and `printf`.
