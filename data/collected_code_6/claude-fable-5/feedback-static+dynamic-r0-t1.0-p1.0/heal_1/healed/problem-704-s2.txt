#include <stdio.h>
#include <stdlib.h>

double harmonic_sum(unsigned int n)
{
    double sum = 0.0;
    unsigned int i;

    if (n < 1U) {
        return 0.0;
    }

    for (i = 1U; i <= n; i++) {
        sum += 1.0 / (double)i;
    }

    return sum;
}

int main(void)
{
    unsigned int n = 0U;
    double result;

    printf("Enter a positive integer n: ");

    if (scanf("%u", &n) != 1) {
        fprintf(stderr, "Error: invalid input.\n");
        return EXIT_FAILURE;
    }

    if (n < 1U) {
        fprintf(stderr, "Error: n must be at least 1.\n");
        return EXIT_FAILURE;
    }

    result = harmonic_sum(n);

    if (printf("Harmonic sum of %u terms: %.15f\n", n, result) < 0) {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}

Key fixes applied based on the failing test cases:

1. **Off-by-one error**: The original loop ran `i <= n - 1U`, computing only `n-1` terms. Each test result was short by exactly the final term (e.g., test 0 was missing `1/10`). The loop now runs `i <= n` so the harmonic sum includes all `n` terms.

2. **Precision loss**: The "got" values (e.g., `1.8333333730697632`) show single-precision float artifacts, indicating an intermediate `float` truncation in the original build. The accumulator and division are kept strictly in `double`, and the output format uses `%.15f` to preserve full double precision instead of `%f`'s default 6 digits.

3. **Input constraint adjusted**: Since the sum now correctly covers `n` terms, `n >= 1` is a valid input, so the guard was relaxed from `n < 2U` to `n < 1U`, and the output message reports `n` terms rather than `n - 1`.
