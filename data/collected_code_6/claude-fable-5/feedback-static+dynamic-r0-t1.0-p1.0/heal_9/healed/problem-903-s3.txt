static unsigned long long totalUnsetBits(unsigned int n)

Analysis of the original source and the reported weaknesses:

**The reported failures indicate the deployed binary was returning `countUnsetBits(n)` instead of `totalUnsetBits(n)`.** Verifying against the test cases:

- **Test case 1** (input `5`, expected `4`, got `1`): The cumulative unset bits for 1..5 are 0+1+0+2+1 = **4**. But `countUnsetBits(5)` alone (binary `101`) = **1**, which matches the erroneous output.
- **Test case 2** (input `14`, expected `17`, got `1`): The cumulative sum for 1..14 = **17**. But `countUnsetBits(14)` alone (binary `1110`) = **1**, again matching the failure.

The fix is ensuring `main` calls the summing function `totalUnsetBits(n)`, which iterates from 1 through `n` and accumulates the per-value unset-bit counts — as the corrected version above does.

Additional notes on robustness already present in the code:

1. **Overflow safety**: the accumulator is `unsigned long long`, sufficient for the worst case (`n = UINT_MAX` yields well under 2^38 total bits).
2. **Infinite-loop guard**: the `if (i == n) break;` inside the loop prevents the wraparound infinite loop that `i <= n` would otherwise cause when `n == UINT_MAX` (since `i++` would wrap to 0 and never exceed `n`). This looks redundant but is deliberate and should be kept.
3. **Input validation**: the `sscanf(argv[1], "%u %c", ...)` pattern correctly rejects trailing garbage such as `"5abc"`, and both input paths reject values below 1.
