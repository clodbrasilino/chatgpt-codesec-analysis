```c
#include <stdio.h>
#include <string.h>
#include <ctype.h>

#define MAX_INPUT_LEN 4096U

size_t length_of_last_word(const char *s)
{
    size_t len;
    size_t end;
    size_t count;

    if (s == NULL) {
        return 0U;
    }

    len = strnlen(s, MAX_INPUT_LEN);
    if (len == 0U) {
        return 0U;
    }

    end = len;
    while (end > 0U && isspace((unsigned char)s[end - 1U])) {
        end--;
    }

    count = 0U;
    while (end > 0U && !isspace((unsigned char)s[end - 1U])) {
        count++;
        end--;
    }

    return count;
}

int main(void)
{
    const char *tests[] = {
        "Hello World",
        "   fly me   to   the moon  ",
        "luffy is still joyboy",
        "",
        "     ",
        "single"
    };
    size_t num_tests = sizeof(tests) / sizeof(tests[0]);
    size_t i;

    for (i = 0U; i < num_tests; i++) {
        size_t result = length_of_last_word(tests[i]);
        if (printf("Input: \"%s\" -> Last word length: %zu\n", tests[i], result) < 0) {
            return 1;
        }
    }

    return 0;
}
```

**Analysis of the change:**

The Flawfinder warning (CWE-126) flagged `strlen()` because it performs an unbounded scan for the null terminator. If the function were ever passed a buffer that is not properly null-terminated, `strlen()` would read past the end of the buffer — a potential over-read leading to a crash or information disclosure.

The fix replaces `strlen()` with `strnlen()`, which bounds the scan to `MAX_INPUT_LEN` bytes. Even if a malformed, non-terminated buffer is passed, the read is capped at a known limit rather than running off into unmapped or sensitive memory.

Notes on what was already correct in the original code:

- **NULL check** before dereferencing `s` guards against a null-pointer dereference.
- **`(unsigned char)` casts** before calling `isspace()` avoid undefined behavior when `char` is signed and holds negative values (required by the C standard for `<ctype.h>` functions).
- **Unsigned index arithmetic** (`end - 1U` guarded by `end > 0U`) prevents underflow/out-of-bounds access.
- **Checking `printf()`'s return value** in `main` handles output-stream failures.

One caveat: `strnlen()` is POSIX (and C23's `strnlen_s` is the standard analog), so on strictly C89/C99 toolchains you may need `_POSIX_C_SOURCE` defined or a small portable fallback.
