static size_t bounded_len(const char *s, size_t max)

    size_t i = 0;

    while (i < max && s[i] != '\0') {
        i++;
    }
    return i;
}

**Analysis summary of the changes:**

1. **Test case failures (`<no output>` for all three cases):** The original code read input with two separate `fgets()` calls, which requires each string to be on its own line. If the test harness supplies both binary strings on a single line (whitespace-separated), the second `fgets()` fails and the program either behaves unexpectedly or the harness sees no matching output. Switching to `scanf("%4095s", ...)` tokenizes on any whitespace (spaces or newlines), so the program now works regardless of whether the two strings are on one line or two. This also makes `strip_newline()` unnecessary, since `%s` never includes newline characters.

2. **Flawfinder CWE-119/CWE-120 (buffer overflow on statically-sized arrays):** The `scanf` format specifier uses an explicit field width of `4095` (`MAX_LEN - 1`), guaranteeing no more than 4095 characters plus the null terminator are written into each 4096-byte buffer. Buffers are also zero-initialized with `memset` and explicitly null-terminated at the last index as defense in depth, and `bounded_len()` still enforces the length cap inside `min_swaps()`.

3. **Algorithm correctness retained:** `min_swaps()` correctly returns the count of `(1,0)` mismatches, which equals the minimum number of swaps needed within `s1` to match `s2`, and returns `-1` ("Not Possible") when lengths differ, characters aren't binary, or the mismatch counts are unbalanced (differing number of `1`s).
