```c
#include <stdio.h>
#include <limits.h>
#include <stddef.h>

long long max_subarray_sum(const int *arr, size_t n, int *status)
{
    if (arr == NULL || n == 0U || status == NULL) {
        if (status != NULL) {
            *status = -1;
        }
        return 0;
    }

    long long best = (long long)arr[0];
    long long current = (long long)arr[0];

    for (size_t i = 1U; i < n; i++) {
        long long value = (long long)arr[i];

        if (current > 0) {
            if (value > 0 && current > LLONG_MAX - value) {
                *status = -2;
                return 0;
            }
            current = current + value;
        } else {
            current = value;
        }

        if (current > best) {
            best = current;
        }
    }

    *status = 0;
    return best;
}

int main(void)
{
    int data[] = { -2, 1, -3, 4, -1, 2, 1, -5, 4 };
    size_t n = sizeof(data) / sizeof(data[0]);
    int status = 0;

    long long result = max_subarray_sum(data, n, &status);

    if (status != 0) {
        if (fprintf(stderr, "Error: invalid input or overflow\n") < 0) {
            return 1;
        }
        return 1;
    }

    if (printf("Largest contiguous subarray sum: %lld\n", result) < 0) {
        return 1;
    }

    return 0;
}
```

**Analysis of the fix:**

The original code used `if (current + value > value)` as an implicit overflow-aware way of testing whether extending the running subarray is beneficial. This is broken for two reasons:

1. **Undefined behavior on overflow:** If `current + value` overflows `long long`, the behavior is undefined. Compilers (GCC, Clang with `-O2`) legally assume signed overflow never happens and rewrite the condition to `current > 0`, silently discarding any intended overflow protection.

2. **It never actually detected overflow:** Even if overflow wrapped predictably, the comparison logic doesn't reliably distinguish an overflowed sum from a legitimate one.

The rewritten version:

- Uses the mathematically equivalent, well-defined Kadane's condition `current > 0` directly, which is what the algorithm actually intends.
- Adds a **pre-condition overflow guard** (`current > LLONG_MAX - value`) that checks *before* performing the addition, so no UB can occur. Since `current > 0` is already established, only the positive-overflow direction needs checking; adding a negative or zero `value` to a positive `current` cannot overflow.
- Reports overflow through the existing `status` out-parameter (`-2`) rather than returning a garbage value, keeping the error-reporting contract consistent with the null-pointer/empty-array case.

Note that in practice, summing `int` values into a `long long` accumulator would require roughly 2³² maximum-valued elements to overflow, but the guard makes the function robust regardless of input size and eliminates the static-analysis finding entirely.
