```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>

#define MAX_INPUT 1024

size_t count_vowels(const char *str)
{
    size_t count = 0;
    size_t i;

    if (str == NULL) {
        return 0;
    }

    for (i = 0; str[i] != '\0'; i++) {
        int c = tolower((unsigned char)str[i]);
        if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u') {
            count++;
        }
    }

    return count;
}

static void flush_stdin(void)
{
    int ch;

    do {
        ch = getchar();
    } while (ch != '\n' && ch != EOF);
}

int main(void)
{
    char buffer[MAX_INPUT];
    size_t len;
    size_t vowels;

    printf("Enter a string: ");
    fflush(stdout);

    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if (len > 0 && buffer[len - 1] == '\n') {
        buffer[len - 1] = '\0';
    } else if (len == sizeof(buffer) - 1) {
        flush_stdin();
    }

    vowels = count_vowels(buffer);
    printf("Number of vowels: %zu\n", vowels);

    return EXIT_SUCCESS;
}
```

**Analysis of the flagged weaknesses:**

Both Flawfinder findings are effectively false positives in this code, and the original mitigations remain correct:

1. **`getchar` in a loop (CWE-120, CWE-20)** — The `flush_stdin()` loop never stores characters into a buffer; it merely discards them until newline or EOF. There is no buffer to overflow, so the risk-1 warning does not apply. The `EOF` check also prevents an infinite loop if stdin is closed.

2. **Statically-sized `char` array (CWE-119/CWE-120)** — The buffer is only written to via `fgets(buffer, sizeof(buffer), stdin)`, which enforces the bound. Defense-in-depth is already present:
   - Explicit null termination at `buffer[sizeof(buffer) - 1]`.
   - `strnlen` bounded by `sizeof(buffer)` instead of unbounded `strlen`.
   - Trailing-newline stripping with a `len > 0` guard against underflow.
   - Draining leftover input when the line was truncated, preventing stale data from affecting subsequent reads.

3. **`count_vowels` hardening** — The `NULL` check and the `(unsigned char)` cast before `tolower()` avoid undefined behavior for negative `char` values (e.g., high-bit characters on platforms with signed `char`).

The code is safe as written; no functional changes were required beyond removing the annotation comments.
