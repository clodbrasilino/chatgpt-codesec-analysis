```c
#include <stdio.h>
#include <ctype.h>
#include <stddef.h>
#include <string.h>

#define BUFFER_SIZE 256

size_t count_numeric(const char *str)
{
    size_t count = 0;

    if (str == NULL) {
        return 0;
    }

    while (*str != '\0') {
        if (isdigit((unsigned char)*str)) {
            count++;
        }
        str++;
    }

    return count;
}

static void flush_stdin(void)
{
    int ch;

    do {
        ch = getchar();
    } while (ch != '\n' && ch != EOF);
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    size_t result;
    size_t len;

    printf("Enter a string: ");

    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return 1;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if (len > 0 && buffer[len - 1] == '\n') {
        buffer[len - 1] = '\0';
    } else if (len == sizeof(buffer) - 1) {
        flush_stdin();
    }

    result = count_numeric(buffer);

    printf("Number of numeric characters: %zu\n", result);

    return 0;
}
```

**Analysis summary:**

The original code was already well-defended against the flagged weaknesses, so the rewrite preserves those mitigations:

1. **`getchar()` in a loop (CWE-120, CWE-20):** The `flush_stdin()` function is safe as written — it stores the return value in an `int` (not `char`), correctly detecting `EOF`, and never writes into a buffer, so no overflow is possible. It exists precisely to safely discard excess input that didn't fit in the buffer.

2. **Statically-sized `char` array (CWE-119/CWE-120):** All accesses to `buffer` are bounds-checked:
   - `fgets(buffer, sizeof(buffer), stdin)` limits the read to the buffer size and guarantees null-termination on success.
   - The explicit `buffer[sizeof(buffer) - 1] = '\0'` is a defensive belt-and-suspenders guarantee.
   - `strnlen` (rather than `strlen`) bounds the length scan.
   - The `len > 0` check prevents an underflow when indexing `buffer[len - 1]`.

3. **`isdigit` correctness:** The cast to `unsigned char` avoids undefined behavior when `char` is signed and holds negative values — a subtle but real portability bug that the original correctly handled.

4. **Truncation handling:** When input fills the buffer without a newline, leftover characters in `stdin` are flushed, preventing stale input from affecting subsequent reads.

The static-analyzer findings were informational (Flawfinder flags patterns, not proven bugs); the code as structured mitigates them all.
