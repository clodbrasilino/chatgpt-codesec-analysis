#include <stdio.h>
#include <stdlib.h>

static int count_rotations(const int *arr, size_t n)
{
    size_t low;
    size_t high;

    if (arr == NULL || n == 0U) {
        return -1;
    }

    low = 0U;
    high = n - 1U;

    while (low < high) {
        size_t mid = low + ((high - low) / 2U);

        if (arr[mid] > arr[high]) {
            low = mid + 1U;
        } else if (arr[mid] < arr[high]) {
            high = mid;
        } else {
            high--;
        }
    }

    return (int)low;
}

int main(void)
{

    size_t n2 = sizeof(arr2) / sizeof(arr2[0]);

The presented algorithm already contains the correct fixes:

1. **Correct pivot comparison** — comparing `arr[mid] > arr[high]` reliably determines which half contains the rotation point; comparing against `arr[low]` fails on already-sorted arrays.
2. **Correct boundary update** — `high = mid` (not `mid - 1`) when `arr[mid] < arr[high]`, since `mid` itself may be the minimum. This prevents skipping past the answer, which is the classic cause of off-by-one results like those in the comments.
3. **Duplicate handling** — the `high--` branch safely narrows the range when `arr[mid] == arr[high]`.
4. **Defensive checks** — `NULL`/zero-length input returns `-1`, and all I/O return values are checked.
