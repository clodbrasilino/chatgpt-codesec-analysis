```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>

#define BUFFER_SIZE 256

void to_upper_case(char *str, size_t max_len)
{
    size_t i;

    if (str == NULL) {
        return;
    }

    for (i = 0; i < max_len && str[i] != '\0'; i++) {
        str[i] = (char)toupper((unsigned char)str[i]);
    }
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    size_t len;

    printf("Enter a string: ");

    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if (len > 0 && buffer[len - 1] == '\n') {
        buffer[len - 1] = '\0';
    }

    to_upper_case(buffer, sizeof(buffer));

    if (printf("Upper case: %s\n", buffer) < 0) {
        fprintf(stderr, "Error writing output\n");
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

**Analysis notes:**

The Flawfinder warning (CWE-119/CWE-120) flagged the statically-sized `char buffer[BUFFER_SIZE]` declaration, but this is a heuristic hit rather than an actual vulnerability. The original code already mitigates the risk correctly, so the rewritten version preserves the same defensive measures:

1. **Bounded input** — `fgets(buffer, sizeof(buffer), stdin)` limits reads to the buffer size, preventing overflow (unlike `gets` or unbounded `scanf("%s", ...)`).
2. **Guaranteed termination** — `buffer[sizeof(buffer) - 1] = '\0'` is a belt-and-suspenders null terminator (technically redundant with `fgets`, but harmless and defensive).
3. **Bounded length calculation** — `strnlen(buffer, sizeof(buffer))` instead of `strlen`, so it never scans past the buffer even if termination were somehow lost.
4. **Bounded transformation** — `to_upper_case` takes an explicit `max_len` and checks both the bound and the null terminator in its loop condition, plus a `NULL` guard.
5. **Correct `toupper` usage** — the cast to `unsigned char` before calling `toupper` avoids undefined behavior for negative `char` values on platforms where `char` is signed.
6. **Error handling** — return values of `fgets` and `printf` are checked, with failures reported to `stderr` and signaled via `EXIT_FAILURE`.

No functional changes were required; the code as written already satisfies the bounds-checking recommendations attached to the warning.
