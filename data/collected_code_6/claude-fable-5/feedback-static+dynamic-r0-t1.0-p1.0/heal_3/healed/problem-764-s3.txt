```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>

#define BUFFER_SIZE 256

size_t count_numeric(const char *str)
{
    size_t count;
    size_t i;

    if (str == NULL) {
        return 0;
    }

    count = 0;
    for (i = 0; str[i] != '\0'; i++) {
        if (isdigit((unsigned char)str[i])) {
            count++;
        }
    }

    return count;
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    size_t result;

    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';
    buffer[strcspn(buffer, "\n")] = '\0';

    result = count_numeric(buffer);

    if (printf("Numeric characters: %zu\n", result) < 0) {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

**Analysis notes:**

The original code was already well-hardened against the flagged weakness (CWE-119/CWE-120, buffer overflow risks with statically-sized arrays). The rewritten version preserves all of the existing mitigations:

1. **Bounded input reading** — `fgets(buffer, sizeof(buffer), stdin)` limits the read to the buffer size, preventing overflow. Using `sizeof(buffer)` rather than a hardcoded value keeps the bound correct even if `BUFFER_SIZE` changes.

2. **Guaranteed null termination** — `buffer[sizeof(buffer) - 1] = '\0';` is defensive (technically redundant, since `fgets` always null-terminates on success, but it costs nothing and protects against future refactoring).

3. **Safe newline stripping** — `strcspn(buffer, "\n")` avoids the classic unsafe idiom `buffer[strlen(buffer) - 1] = '\0'`, which invokes undefined behavior on an empty string.

4. **NULL guard in `count_numeric`** — protects against misuse of the helper function.

5. **Correct `isdigit` usage** — the cast to `unsigned char` avoids undefined behavior when `char` is signed and the input contains bytes with values above 127.

6. **Return value checking** — both `fgets` and `printf` results are checked, with appropriate exit statuses via `EXIT_SUCCESS`/`EXIT_FAILURE`.

No functional changes were required; the Flawfinder hit is a low-risk informational warning about the mere presence of a fixed-size buffer, and the code already performs the bounds checking it recommends.
