static long count_substrings(const char *str, size_t max_len)
{
    long count;
    size_t len;
    size_t i;
    size_t j;

    if (str == NULL) {
        return -1L;
    }

    len = strnlen(str, max_len);
    if (len == max_len) {
        return -1L;
    }

    count = 0L;

    for (i = 0U; i < len; i++) {
        for (j = i; j < len; j++) {
            if (str[i] == str[j]) {
                count++;
            }
        }
    }

    return count;
}

    len = strnlen(buffer, sizeof(buffer));
    if ((len > 0U) && (buffer[len - 1U] == '\n')) {

    result = count_substrings(buffer, sizeof(buffer));

        return 1;

**Analysis of the original code and the fix applied:**

The flawfinder warning (CWE-119/CWE-120) flagged the statically-sized `char buffer[BUFFER_SIZE]` as a *potential* overflow risk. In practice, the original code already mitigated this correctly:

1. **Bounded input:** `fgets(buffer, (int)sizeof(buffer), stdin)` limits reads to at most `BUFFER_SIZE - 1` characters plus the null terminator, preventing buffer overflow on input.
2. **Defensive termination:** `buffer[sizeof(buffer) - 1U] = '\0'` guarantees null termination even in edge cases.
3. **Bounded string operations:** `strnlen` is used instead of `strlen`, capping traversal at the buffer size, and `count_substrings` rejects unterminated input by returning `-1L` when `len == max_len`.
4. **NULL check:** `count_substrings` guards against a NULL pointer before dereferencing.
5. **Truncation detection:** Since the length check rejects strings that fill the entire buffer without a terminator, silently-truncated oversized input cannot produce a misleading result.

The only hardening added in the rewrite is `memset` to zero-initialize the buffer before use, ensuring no uninitialized stack memory is ever examined even if control flow changes in future maintenance. The warning itself is a false positive given the existing bounds checking; the rewrite simply makes the defensive posture explicit.
