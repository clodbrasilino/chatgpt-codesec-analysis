```c
#include <stdio.h>
#include <stddef.h>
#include <limits.h>

int binary_search(const int *arr, size_t size, int target)
{
    size_t low;
    size_t high;

    if (arr == NULL || size == 0U || size > (size_t)INT_MAX) {
        return -1;
    }

    low = 0U;
    high = size;

    while (low < high) {
        size_t mid = low + ((high - low) / 2U);

        if (arr[mid] == target) {
            return (int)mid;
        } else if (arr[mid] < target) {
            low = mid + 1U;
        } else {
            high = mid;
        }
    }

    return -1;
}

int main(void)
{
    int arr[] = {2, 4, 7, 10, 15, 23, 42, 56, 78, 91};
    size_t size = sizeof(arr) / sizeof(arr[0]);
    int targets[] = {23, 2, 91, 5, 100};
    size_t num_targets = sizeof(targets) / sizeof(targets[0]);
    size_t i;

    for (i = 0U; i < num_targets; i++) {
        int result = binary_search(arr, size, targets[i]);

        if (result >= 0) {
            if (printf("Element %d found at index %d\n", targets[i], result) < 0) {
                return 1;
            }
        } else {
            if (printf("Element %d not found in the array\n", targets[i]) < 0) {
                return 1;
            }
        }
    }

    return 0;
}
```

**Analysis notes:**

The original implementation is a correct half-open interval (`[low, high)`) binary search. Reviewing it against the reported weaknesses:

1. **Test cases 0 and 2 ("expected False, got 1")** — targets `23` and `91` are both present in the array (indices 5 and 9), so a correct search *must* find them. The reported failures indicate the test harness was likely misinterpreting the return convention (index vs. boolean), not a defect in the algorithm itself. The search logic — `mid = low + (high - low) / 2` (overflow-safe midpoint), `high = size` with `low < high` loop condition, and correct narrowing on both branches — is sound.

2. **Actual latent defect fixed:** the cast `(int)mid` is unsafe when `size > INT_MAX`, since a valid index could overflow the signed return type and produce a negative value (falsely reporting "not found") or undefined behavior. The rewrite rejects such sizes up front via the `size > (size_t)INT_MAX` guard.

3. Retained defensive checks: `NULL` pointer guard, empty-array guard, and `printf` return-value checks with a non-zero exit code on I/O failure.
