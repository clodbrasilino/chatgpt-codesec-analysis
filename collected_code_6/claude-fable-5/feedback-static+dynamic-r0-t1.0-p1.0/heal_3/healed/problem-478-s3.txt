```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>

#define MAX_INPUT_LEN 4096

char *remove_lowercase(const char *input)
{
    size_t len;
    size_t i;
    size_t j;
    char *result;

    if (input == NULL) {
        return NULL;
    }

    len = strnlen(input, MAX_INPUT_LEN);

    result = malloc(len + 1);
    if (result == NULL) {
        return NULL;
    }

    j = 0;
    for (i = 0; i < len; i++) {
        if (!islower((unsigned char)input[i])) {
            result[j] = input[i];
            j++;
        }
    }
    result[j] = '\0';

    return result;
}

int main(void)
{
    char buffer[MAX_INPUT_LEN];

    while (fgets(buffer, sizeof(buffer), stdin) != NULL) {
        size_t len = strnlen(buffer, sizeof(buffer));

        while (len > 0 && (buffer[len - 1] == '\n' || buffer[len - 1] == '\r')) {
            buffer[len - 1] = '\0';
            len--;
        }

        char *output = remove_lowercase(buffer);
        if (output == NULL) {
            fprintf(stderr, "Memory allocation failed\n");
            return EXIT_FAILURE;
        }

        printf("%s\n", output);
        free(output);
    }

    return EXIT_SUCCESS;
}
```

The key changes made to address the identified weaknesses:

1. **Variable scope reduction (`output` and `len`)**: Both variables are now declared inside the `while` loop where they are actually used, limiting their scope as recommended by the static analyzer.

2. **`strlen` over-read risk (CWE-126)**: Replaced `strlen` with `strnlen(buffer, sizeof(buffer))`, which guarantees the read is bounded by the buffer size even if the string were somehow not null-terminated. In practice `fgets` always null-terminates, but this satisfies the analyzer and adds defense in depth.

3. **Statically-sized buffer (CWE-119/CWE-120)**: This is a low-risk informational finding. The buffer usage is already safe because `fgets(buffer, sizeof(buffer), stdin)` performs proper bounds checking, and all subsequent operations (`strnlen`, the trailing newline strip loop) are length-bounded. No overflow is possible here, so the array is retained with its safe usage pattern intact.

The `remove_lowercase` function was already sound: it null-checks its input, bounds the length with `strnlen`, checks the `malloc` result, casts to `unsigned char` before calling `islower` (avoiding undefined behavior with negative `char` values), and properly null-terminates the result.
