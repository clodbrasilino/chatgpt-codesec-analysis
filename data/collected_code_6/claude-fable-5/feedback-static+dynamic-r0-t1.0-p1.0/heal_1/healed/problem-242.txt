#include <stdio.h>
#include <stddef.h>

#define BUFFER_SIZE 256

size_t count_characters(const char *str, size_t max_len)
{
    size_t count = 0;

    if (str == NULL)
    {
        return 0;
    }

    while (count < max_len && str[count] != '\0')
    {
        count++;
    }

    return count;
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    size_t length;
    size_t i;

    printf("Enter a string: ");

    if (fgets(buffer, sizeof(buffer), stdin) == NULL)
    {
        fprintf(stderr, "Error reading input\n");
        return 1;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    length = count_characters(buffer, sizeof(buffer));

    for (i = 0; i < length; i++)
    {
        if (buffer[i] == '\n')
        {
            buffer[i] = '\0';
            break;
        }
    }

    length = count_characters(buffer, sizeof(buffer));

    printf("Total characters: %zu\n", length);

    return 0;
}

**Analysis of the original code and fixes applied:**

The Flawfinder warning (CWE-119/CWE-120) flagged the statically-sized `char buffer[256]` as a potential overflow risk. The original code was actually already fairly safe since it used `fgets` with `sizeof(buffer)`, but the rewritten version hardens it further:

1. **Bounded string traversal** — `count_characters` now takes a `max_len` parameter, guaranteeing it can never read past the end of the buffer even if the string is somehow not null-terminated. This directly mitigates the CWE-119 out-of-bounds read concern.

2. **Explicit null termination** — `buffer[sizeof(buffer) - 1] = '\0'` is a defensive guarantee that the buffer is always a valid C string before any traversal, regardless of what `fgets` did.

3. **Named constant** — `BUFFER_SIZE` replaces the magic number, making the size restriction explicit and maintainable, addressing the "ensure the size is larger than the maximum possible length" guidance.

4. **`sizeof(buffer)` used consistently** — both in `fgets` and in the bounds passed to `count_characters`, so the buffer size is defined in exactly one place and cannot drift out of sync.
