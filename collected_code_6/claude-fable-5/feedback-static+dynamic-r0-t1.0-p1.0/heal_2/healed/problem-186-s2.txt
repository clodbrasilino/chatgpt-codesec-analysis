## Analysis

The code is generally well-written: it validates input pointers, checks all return codes from `regcomp`/`regexec`, calls `regfree` on every exit path (no leaks), and uses `regerror` with an explicit buffer size. The Flawfinder warning concerns the statically-sized `error_msg[MAX_ERROR_MSG]` buffer (CWE-119/CWE-120). In practice the existing code already mitigates it — `regerror` receives `sizeof(error_msg)` and the buffer is explicitly NUL-terminated — but the mitigation can be made more robust by querying `regerror` for the *required* size first and allocating exactly that, eliminating any fixed-size assumption entirely. A secondary latent issue: the function is named `search_literal` yet passes the pattern straight to `regcomp`, so regex metacharacters in the "literal" would be interpreted; escaping them makes the behavior match the name.

## Rewritten code

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <regex.h>

static void print_regex_error(int errcode, const regex_t *regex, const char *context)
{
    size_t needed = regerror(errcode, regex, NULL, 0);
    char *error_msg = malloc(needed);

    if (error_msg != NULL) {
        regerror(errcode, regex, error_msg, needed);
        fprintf(stderr, "%s: %s\n", context, error_msg);
        free(error_msg);
    } else {
        fprintf(stderr, "%s: error code %d (message allocation failed)\n",
                context, errcode);
    }
}

static char *escape_literal(const char *literal)
{
    size_t len = strlen(literal);
    size_t i;
    size_t j = 0;
    char *escaped;

    if (len > (SIZE_MAX - 1) / 2) {
        return NULL;
    }

    escaped = malloc(len * 2 + 1);
    if (escaped == NULL) {
        return NULL;
    }

    for (i = 0; i < len; i++) {
        if (strchr(".^$*+?()[]{}|\\", literal[i]) != NULL) {
            escaped[j++] = '\\';
        }
        escaped[j++] = literal[i];
    }
    escaped[j] = '\0';

    return escaped;
}

int search_literal(const char *text, const char *literal, size_t *offset)
{
    regex_t regex;
    regmatch_t match;
    char *pattern;
    int ret;

    if (text == NULL || literal == NULL || offset == NULL) {
        return -1;
    }

    pattern = escape_literal(literal);
    if (pattern == NULL) {
        fprintf(stderr, "failed to prepare pattern\n");
        return -1;
    }

    ret = regcomp(&regex, pattern, REG_NEWLINE);
    free(pattern);

    if (ret != 0) {
        print_regex_error(ret, &regex, "regcomp failed");
        return -1;
    }

    ret = regexec(&regex, text, 1, &match, 0);
    if (ret == 0) {
        *offset = (size_t)match.rm_so;
        regfree(&regex);
        return 1;
    }

    if (ret == REG_NOMATCH) {
        regfree(&regex);
        return 0;
    }

    print_regex_error(ret, &regex, "regexec failed");
    regfree(&regex);
    return -1;
}

int main(void)
{
    const char *text = "The quick brown fox jumps over the lazy dog";
    const char *literals[] = { "quick", "fox", "cat", "lazy" };
    size_t count = sizeof(literals) / sizeof(literals[0]);
    size_t i;
    size_t offset = 0;
    int status = EXIT_SUCCESS;

    for (i = 0; i < count; i++) {
        int result = search_literal(text, literals[i], &offset);
        if (result == 1) {
            printf("Found \"%s\" at offset %zu\n", literals[i], offset);
        } else if (result == 0) {
            printf("\"%s\" not found\n", literals[i]);
        } else {
            fprintf(stderr, "Error searching for \"%s\"\n", literals[i]);
            status = EXIT_FAILURE;
        }
    }

    return status;
}
```

## Key changes

1. **CWE-119/CWE-120 fix**: replaced the fixed `char error_msg[MAX_ERROR_MSG]` buffer with a two-pass `regerror` call — first querying the exact required size (`regerror(code, regex, NULL, 0)`), then allocating precisely that amount. No fixed-size buffer, no truncation, no possibility of overflow.
2. **Metacharacter escaping**: `escape_literal()` ensures the pattern is treated as a true literal string, preventing unexpected regex interpretation (and potential ReDoS if the literal came from untrusted input), with an overflow guard on the `len * 2 + 1` allocation size.
3. **Preserved semantics**: return codes (`1` found, `0` not found, `-1` error), NULL checks, and `regfree` on all paths are retained; expected output for the sample input is unchanged.
