```c
#include <stdio.h>
#include <string.h>
#include <limits.h>
#include <stddef.h>

#define MAX_INPUT_SIZE 1024

long long countSubstrings(const char *str, size_t max_len)
{
    long long counts[UCHAR_MAX + 1] = {0};
    long long result = 0;
    size_t i;
    size_t len;

    if (str == NULL || max_len == 0) {
        return 0;
    }

    len = strnlen(str, max_len);

    for (i = 0; i < len; i++) {
        counts[(unsigned char)str[i]]++;
    }

    for (i = 0; i <= UCHAR_MAX; i++) {
        result += (counts[i] * (counts[i] + 1)) / 2;
    }

    return result;
}

int main(void)
{
    char buffer[MAX_INPUT_SIZE];
    long long result;

    memset(buffer, 0, sizeof(buffer));

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return 1;
    }

    buffer[sizeof(buffer) - 1] = '\0';
    buffer[strcspn(buffer, "\n")] = '\0';

    result = countSubstrings(buffer, sizeof(buffer));

    if (printf("%lld\n", result) < 0) {
        return 1;
    }

    return 0;
}
```

Analysis of the original code and the identified weakness:

**The Flawfinder warning (CWE-119/CWE-120)** flagged the statically-sized `char buffer[MAX_INPUT_SIZE]` declaration. This is a heuristic warning — static analysis tools flag all fixed-size buffers because they are *potential* overflow sites. However, the original code already mitigates this correctly, so the rewrite preserves the existing defenses:

1. **Bounded input reading**: `fgets(buffer, (int)sizeof(buffer), stdin)` limits input to the buffer size, writing at most `sizeof(buffer) - 1` characters plus a null terminator. This prevents the classic `gets()`-style overflow (CWE-120).

2. **Guaranteed null termination**: `buffer[sizeof(buffer) - 1] = '\0'` is defensive redundancy — `fgets` already null-terminates, but this makes the invariant explicit.

3. **Bounded string measurement**: `countSubstrings` uses `strnlen(str, max_len)` instead of `strlen`, so even a non-terminated buffer cannot cause an out-of-bounds read (CWE-125).

4. **NULL and zero-length guards**: The function validates `str != NULL` and `max_len != 0` before any access.

5. **Safe indexing**: The cast `(unsigned char)str[i]` prevents negative array indices on platforms where `char` is signed — indexing `counts[]` with a negative value would be undefined behavior.

6. **Newline stripping via `strcspn`**: Safe idiom that never indexes out of bounds, unlike the common buggy `buffer[strlen(buffer) - 1] = '\0'` pattern which underflows on empty strings.

One residual (theoretical) concern: `counts[i] * (counts[i] + 1) / 2` could overflow `long long` only if a single character appeared ~4.3 billion times, which is impossible given the 1024-byte buffer, so it is safe in this context.
