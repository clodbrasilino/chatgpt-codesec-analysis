static size_t bounded_len(const char *s, size_t max_len)

            break;
        }
    }

Key changes made as an experienced C developer reviewing the flagged weaknesses:

1. **Removed `strnlen`** — this is the likely cause of all three test failures (`<no output>`). `strnlen` is a POSIX function, not part of standard C90/C99, so strict compilation (e.g., `-std=c99 -Werror`) fails with an implicit declaration error, producing a binary that never builds and thus no output. It is replaced with a portable `bounded_len` helper that never over-reads past `MAX_INPUT_LEN` (addressing the CWE-126 over-read concern too).

2. **`strlen` in `strip_newline` replaced** with the same bounded helper, resolving the Flawfinder CWE-126 warning about non-terminated strings causing over-reads.

3. **Defensive termination of the statically-sized buffers** (`s1[sizeof(s1)-1] = '\0'`) after `fgets`, addressing the CWE-119/CWE-120 warnings — although `fgets` already guarantees termination, explicitly forcing it makes the invariant local and auditable.

4. **Bounds checking preserved** — input length is validated against `MAX_INPUT_LEN`, lengths must match, and only `'0'`/`'1'` characters are accepted; anything else yields `Not Possible`, keeping the original correct algorithm (paired `1→0` / `0→1` mismatches, answer `count10`) intact.
