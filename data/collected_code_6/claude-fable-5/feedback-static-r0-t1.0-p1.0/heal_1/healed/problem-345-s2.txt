```c
#include <stdio.h>
#include <stdlib.h>

int compute_differences(const int *list, size_t n, int *diffs)
{
    size_t i;

    if (list == NULL || diffs == NULL || n < 2) {
        return -1;
    }

    for (i = 0; i < n - 1; i++) {
        diffs[i] = list[i + 1] - list[i];
    }

    return 0;
}

int main(void)
{
    int numbers[] = {10, 15, 7, 22, 30, 28};
    size_t n = sizeof(numbers) / sizeof(numbers[0]);
    int *diffs;
    size_t i;

    diffs = malloc((n - 1) * sizeof(*diffs));
    if (diffs == NULL) {
        fprintf(stderr, "Memory allocation failed\n");
        return EXIT_FAILURE;
    }

    if (compute_differences(numbers, n, diffs) != 0) {
        fprintf(stderr, "Failed to compute differences\n");
        free(diffs);
        return EXIT_FAILURE;
    }

    for (i = 0; i < n - 1; i++) {
        if (printf("Difference %zu: %d\n", i + 1, diffs[i]) < 0) {
            free(diffs);
            return EXIT_FAILURE;
        }
    }

    free(diffs);
    diffs = NULL;

    return EXIT_SUCCESS;
}
```

**Analysis of the changes:**

The static-analysis findings (cppcheck's `knownConditionTrueFalse`) flagged that `n` is derived from a fixed-size array at compile time, so `n = 6` is a known constant and the guard `if (n < 2)` in `main` can never be true — it is dead code.

The fix is to remove the redundant, unreachable check from `main`. This is safe because:

1. **The invariant is guaranteed at compile time.** `numbers` is a local array with six initializers, so `sizeof(numbers) / sizeof(numbers[0])` is always 6. There is no runtime path where `n < 2`.

2. **Defensive validation is preserved where it matters.** The `n < 2` check remains inside `compute_differences()`, which is the correct place for it — that function may be reused with arbitrary inputs, so its parameter validation (`list == NULL`, `diffs == NULL`, `n < 2`) is genuinely reachable and must stay.

3. **No behavioral change.** The allocation of `(n - 1) * sizeof(*diffs)` remains well-defined since `n >= 2` is statically guaranteed, avoiding any risk of `size_t` underflow in `n - 1`.

All other aspects of the original code are sound: allocation is checked, `free()` is called on every exit path after allocation, the pointer is nulled after the final free, `printf` return values are checked, and `%zu` is correctly used for `size_t`.
