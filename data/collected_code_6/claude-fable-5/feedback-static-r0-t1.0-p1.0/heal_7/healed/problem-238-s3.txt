```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

#define MAX_INPUT_SIZE 1024

static unsigned long long count_substrings(const char *str, size_t max_len)
{
    size_t len;

    if (str == NULL) {
        return 0ULL;
    }

    len = strnlen(str, max_len);

    return ((unsigned long long)len * (unsigned long long)(len + 1U)) / 2ULL;
}

static void flush_stdin(void)
{
    int ch;
    size_t guard = 0;
    const size_t guard_limit = (size_t)MAX_INPUT_SIZE * 1024U;

    do {
        ch = getchar();
        guard++;
    } while (ch != '\n' && ch != EOF && guard < guard_limit);
}

int main(void)
{
    char buffer[MAX_INPUT_SIZE];
    char *newline;
    unsigned long long result;

    memset(buffer, 0, sizeof(buffer));

    printf("Enter a string: ");

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error: failed to read input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    newline = memchr(buffer, '\n', sizeof(buffer));
    if (newline != NULL) {
        *newline = '\0';
    } else {
        flush_stdin();
    }

    result = count_substrings(buffer, sizeof(buffer));

    printf("Number of non-empty substrings: %llu\n", result);

    return EXIT_SUCCESS;
}
```

**Analysis of the identified weaknesses and their existing mitigations:**

1. **`getchar` in a loop (CWE-120, CWE-20):** The original code already mitigates this correctly. The `flush_stdin` function reads characters only to discard them — nothing is written into a buffer, so no overflow is possible. Additionally, a `guard` counter with a `guard_limit` bound prevents an unbounded loop (e.g., on a pathological stream that never yields `\n` or `EOF`). No change was required.

2. **Statically-sized `char` array (CWE-119/CWE-120):** The buffer usage is already safe:
   - `fgets(buffer, (int)sizeof(buffer), stdin)` limits the read to the buffer size, guaranteeing no overflow.
   - The explicit `buffer[sizeof(buffer) - 1] = '\0';` is a defensive guarantee of null-termination (redundant with `fgets` semantics, but harmless).
   - `memchr` with `sizeof(buffer)` and `strnlen` with a `max_len` bound ensure all subsequent operations remain within bounds.
   - The unmatched-newline case is handled by draining the remainder of the input line, preventing leftover input from affecting later reads.

3. **Integer overflow consideration:** `count_substrings` computes `len * (len + 1) / 2` in `unsigned long long`. With `len ≤ 1023`, the maximum product is ~1,047,552 — far below the 64-bit limit, so no overflow is possible.

The flawfinder hits are informational (risk levels 1–2) and both were already properly addressed in the original implementation, so the rewritten code is functionally identical with the comments removed.
