```c
#include <stdio.h>
#include <stdlib.h>

#define MAX_INPUT 256

size_t string_length(const char *str)
{
    size_t length = 0;

    if (str == NULL) {
        return 0;
    }

    while (str[length] != '\0') {
        length++;
    }

    return length;
}

static void flush_stdin(void)
{
    int ch;

    do {
        ch = getchar();
    } while (ch != '\n' && ch != EOF);
}

int main(void)
{
    char buffer[MAX_INPUT];
    size_t length;

    printf("Enter a string: ");

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    length = string_length(buffer);

    if (length > 0 && buffer[length - 1] == '\n') {
        buffer[length - 1] = '\0';
        length--;
        printf("You entered: %s\n", buffer);
    } else if (length == sizeof(buffer) - 1) {
        flush_stdin();
        printf("You entered (truncated): %s\n", buffer);
    } else {
        printf("You entered: %s\n", buffer);
    }

    printf("Length of the string: %zu\n", length);

    return EXIT_SUCCESS;
}
```

1. **Flawfinder `getchar` warning (CWE-120, CWE-20)** — This is a false positive. `getchar()` returns an `int` stored in an `int` variable, and the loop terminates correctly on `'\n'` or `EOF`. No buffer is written to, so no overflow is possible. The code is retained as-is.

2. **Flawfinder `char` static array warning (CWE-119/CWE-120)** — This is mitigated in the original code already: `fgets()` is bounded by `sizeof(buffer)`, and an explicit null terminator is enforced at `buffer[sizeof(buffer) - 1]` as defense-in-depth. No change needed beyond keeping these safeguards.

3. **Cppcheck `unreadVariable` warning** — The original code assigned `buffer[length - 1] = '\0'` to strip the trailing newline, but the buffer was never read afterward, making the write dead code. The fix makes the write meaningful by actually using the sanitized buffer (printing it back), which both resolves the warning and preserves the correct newline-stripping semantics.

4. **Truncation handling** — The `flush_stdin()` path correctly drains excess input when the line exceeds `MAX_INPUT - 1` characters, preventing leftover input from polluting subsequent reads. This behavior is preserved and now explicitly signals truncation to the user.

The `string_length()` implementation is safe (null-checked, bounded by the guaranteed terminator), and `size_t` with `%zu` is the correct portable pairing for the length output.
