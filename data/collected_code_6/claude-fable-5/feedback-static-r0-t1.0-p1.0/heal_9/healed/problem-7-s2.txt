**Summary of fixes applied:**

1. **CWE-120 (memcpy buffer overflow risk)** — eliminated entirely by removing the `malloc`/`memcpy`/`free` cycle and printing the match directly with `printf("%.*s\n", ...)`. No destination buffer means no overflow possibility and no allocation-failure path inside the loop.

2. **Redundant `remaining > 0` condition** — removed from the loop guard; termination is now handled explicitly at the bottom of the loop where `remaining == 0` is meaningful after decrementing.

3. **`length = end - start` possibly less than 1** — prevented by rejecting matches where `match.rm_eo <= match.rm_so` before any conversion, guaranteeing `length >= 1`.

4. **Always-false condition `length > remaining - start`** — removed. Since `end <= remaining` and `start < end` are already enforced, the check was dead code.

5. **Removed the impossible `length >= (size_t)-1` check** — replaced with a meaningful `length > (size_t)INT_MAX` guard, since `%.*s` requires an `int` width and this prevents a signed conversion overflow.

6. **Unchecked `remaining -= end`** — now provably safe because `end > remaining` breaks the loop first, so the subtraction can never underflow.
