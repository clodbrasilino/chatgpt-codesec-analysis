```c
#include <stdio.h>
#include <stdlib.h>
#include <limits.h>

int max_subarray_sum(const int *arr, size_t n, int *result)
{
    size_t i;
    long long current;
    long long best;

    if (arr == NULL || n == 0 || result == NULL) {
        return -1;
    }

    current = arr[0];
    best = arr[0];

    for (i = 1; i < n; i++) {
        if (current > 0) {
            current = current + arr[i];
        } else {
            current = arr[i];
        }
        if (current > best) {
            best = current;
        }
    }

    if (best > INT_MAX || best < INT_MIN) {
        return -1;
    }

    *result = (int)best;
    return 0;
}

int main(void)
{
    int arr[] = { -2, 1, -3, 4, -1, 2, 1, -5, 4 };
    size_t n = sizeof(arr) / sizeof(arr[0]);
    int result = 0;

    if (max_subarray_sum(arr, n, &result) != 0) {
        fprintf(stderr, "Error: could not compute maximum subarray sum\n");
        return EXIT_FAILURE;
    }

    if (printf("Largest sum of contiguous subarray: %d\n", result) < 0) {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

**Key change explained:**

The flagged weakness was the condition `current + arr[i] > arr[i]`. Although `current` is a `long long` (so the addition itself won't overflow with `int` inputs in practice), this pattern is a classic *invalid overflow test*: static analyzers and optimizing compilers recognize that, in the absence of overflow, the expression is mathematically equivalent to `current > 0`. If the operands had been plain `int`, relying on wraparound here would be undefined behavior, and compilers are entitled to optimize the check away entirely.

The fix replaces it with the semantically equivalent and well-defined condition `current > 0`, which is the canonical form of Kadane's algorithm: extend the running subarray only if its current sum is positive, otherwise restart at the current element. This preserves identical behavior for all valid inputs while eliminating the undefined-behavior-adjacent pattern.

The rest of the code was already sound: NULL/zero-length guards, accumulation in `long long` to avoid intermediate overflow, and a range check against `INT_MAX`/`INT_MIN` before narrowing back to `int`.
