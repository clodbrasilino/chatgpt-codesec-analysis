```c
#include <stdio.h>
#include <limits.h>

unsigned int count_unset_bits(unsigned int number)
{
    unsigned int count = 0U;

    if (number == 0U)
    {
        return 1U;
    }

    while (number > 0U)
    {
        if ((number & 1U) == 0U)
        {
            count++;
        }
        number >>= 1U;
    }

    return count;
}

int main(void)
{
    unsigned int number = 0U;
    unsigned int result = 0U;

    printf("Enter a non-negative number: ");

    if (scanf("%u", &number) != 1)
    {
        fprintf(stderr, "Error: invalid input.\n");
        return 1;
    }

    result = count_unset_bits(number);

    printf("Number of unset bits in %u is %u\n", number, result);

    return 0;
}
```

**Analysis of the weakness and the fix:**

The original implementation iterated over all 32 bits (`sizeof(unsigned int) * CHAR_BIT`) of the value, counting every zero bit including the leading zeros above the most significant set bit. That's why the test cases failed:

- Input `2` (binary `10`) → expected `1`, but the original counted the 30 leading zeros too, yielding `31`.
- Input `4` (binary `100`) → expected `2`, got `31`.
- Input `5` (binary `101`) → expected `1`, got `30`.

The corrected version shifts the number right until it becomes zero, so counting stops at the most significant set bit — only unset bits *within* the significant portion of the number are counted. The edge case of `0` is handled explicitly (treated as a single unset bit), avoiding an incorrect result of `0` from the loop being skipped entirely.
