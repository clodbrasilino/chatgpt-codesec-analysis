```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <ctype.h>

#define BUFFER_SIZE 256

void string_to_lower(char *str)
{
    size_t i;

    if (str == NULL) {
        return;
    }

    for (i = 0; str[i] != '\0'; i++) {
        str[i] = (char)tolower((unsigned char)str[i]);
    }
}

static void flush_stdin(void)
{
    int ch;

    do {
        ch = getchar();
    } while (ch != '\n' && ch != EOF);
}

int main(void)
{
    char buffer[BUFFER_SIZE];

    printf("Enter a string: ");

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    if (strchr(buffer, '\n') == NULL && !feof(stdin)) {
        flush_stdin();
    }

    buffer[strcspn(buffer, "\n")] = '\0';

    string_to_lower(buffer);

    printf("Lowercase: %s\n", buffer);

    return EXIT_SUCCESS;
}
```

**Analysis notes:**

The two weaknesses flagged by Flawfinder are effectively false positives in this code, and the original code already contains the correct mitigations:

1. **`getchar()` in a loop (CWE-120, CWE-20):** The `flush_stdin()` function reads characters into an `int` and discards them — nothing is written to a buffer, so no overflow is possible. Using `int ch` (not `char`) is correct, since it allows a proper comparison against `EOF`.

2. **Statically-sized `char buffer[256]` (CWE-119/CWE-120):** The buffer is only ever filled via `fgets(buffer, sizeof(buffer), stdin)`, which enforces the length limit. The code additionally:
   - Force-terminates with `buffer[sizeof(buffer) - 1] = '\0'` (defensive, though `fgets` already guarantees termination).
   - Detects truncated input (no `\n` present and not at EOF) and drains the remaining characters via `flush_stdin()`, preventing leftover input from polluting subsequent reads.
   - Strips the trailing newline safely with `strcspn`, which cannot go out of bounds.
   - Casts to `unsigned char` before calling `tolower()`, avoiding undefined behavior for negative `char` values.

Since the mitigations are already in place, the rewritten code is functionally identical with the analysis comments removed.
