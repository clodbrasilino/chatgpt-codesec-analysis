```c
#include <stdio.h>
#include <stdlib.h>

int last_two_digits_factorial(int n);

int last_two_digits_factorial(int n)
{
    int result = 1;
    int i;

    if (n < 0) {
        return -1;
    }

    if (n >= 10) {
        return 0;
    }

    for (i = 2; i <= n; i++) {
        result = (result * i) % 100;
    }

    return result;
}

int main(void)
{
    int number = 0;
    int digits = 0;
    int scan_result = 0;

    printf("Enter a non-negative integer: ");

    scan_result = scanf("%d", &number);
    if (scan_result != 1) {
        fprintf(stderr, "Error: invalid input.\n");
        return EXIT_FAILURE;
    }

    digits = last_two_digits_factorial(number);
    if (digits < 0) {
        fprintf(stderr, "Error: factorial is undefined for negative numbers.\n");
        return EXIT_FAILURE;
    }

    printf("Last two digits of %d! are: %02d\n", number, digits);

    return EXIT_SUCCESS;
}
```

**Key design decisions:**

- **Modular arithmetic**: Instead of computing the full factorial (which overflows quickly), I compute `result % 100` at each step, keeping values small and avoiding integer overflow entirely.
- **Early exit for n ≥ 10**: Any factorial of 10 or greater contains the factors 10 and 20 (or 2×5 pairs producing at least two trailing zeros), so the last two digits are always `00`. This avoids unnecessary iteration.
- **CWE-703 compliance**: The return value of `scanf` is checked, and negative input is rejected with a distinct error path rather than producing undefined behavior.
- **CWE-710 compliance**: `main` uses the standard `int main(void)` signature, returns `EXIT_SUCCESS`/`EXIT_FAILURE`, and all variables are initialized before use.
- **CWE-664 compliance**: No dynamically allocated resources or file handles are used, so there are no lifetime management issues; `stdin`/`stdout`/`stderr` are managed by the runtime.
- **`%02d` format**: Ensures results like `2` for `2!` print correctly, and edge cases like `10!` display as `00`.
