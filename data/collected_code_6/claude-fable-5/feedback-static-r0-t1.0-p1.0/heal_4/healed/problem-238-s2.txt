#include <stdio.h>
#include <string.h>

#define BUFFER_SIZE 1024U

unsigned long long count_substrings(const char *str, size_t max_len)
{
    unsigned long long n;

    if (str == NULL)
    {
        return 0ULL;
    }

    n = (unsigned long long)strnlen(str, max_len);

    return (n * (n + 1ULL)) / 2ULL;
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    unsigned long long result;
    size_t len;

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL)
    {
        fprintf(stderr, "Error reading input\n");
        return 1;
    }

    buffer[sizeof(buffer) - 1U] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if (len > 0U && buffer[len - 1U] == '\n')
    {
        buffer[len - 1U] = '\0';
    }

    result = count_substrings(buffer, sizeof(buffer));

    if (printf("%llu\n", result) < 0)
    {
        return 1;
    }

    return 0;
}

**Analysis of the original code and the fix status:**

The Flawfinder warning about the statically-sized `char buffer[BUFFER_SIZE]` (CWE-119/CWE-120) is already properly mitigated in this code, so no functional changes were required:

1. **Bounded input reading** — `fgets(buffer, (int)sizeof(buffer), stdin)` limits input to the buffer size, preventing the classic `gets()`-style overflow.
2. **Guaranteed null termination** — `buffer[sizeof(buffer) - 1U] = '\0'` is defensive; `fgets` already null-terminates, but this makes the invariant explicit.
3. **Bounded string measurement** — `strnlen(buffer, sizeof(buffer))` is used instead of `strlen`, so even a hypothetically unterminated buffer cannot cause an out-of-bounds read.
4. **Safe arithmetic** — substring count uses `unsigned long long`; with `n ≤ 1023`, `n*(n+1)/2` cannot overflow a 64-bit type.
5. **Error handling** — return values of `fgets` and `printf` are checked; `NULL` input to `count_substrings` is handled.

The only remaining theoretical consideration is that input longer than 1023 characters is silently truncated, which is a design decision rather than a memory-safety flaw.
