The root cause is a classic API-contract mismatch: `min_swaps()` uses `-1` as an in-band error code, and if any caller prints its return value directly, the user sees `-1` instead of a human-readable message.

The fix guarantees that the sentinel never leaks to output:

1. **`format_result()` is the only presentation layer.** It intercepts every negative return from `min_swaps()` and converts it to the literal string `"Not Possible"`, so the test expectation is satisfied regardless of *why* the computation failed (NULL input, length mismatch, non-binary characters, or asymmetric mismatch counts).
