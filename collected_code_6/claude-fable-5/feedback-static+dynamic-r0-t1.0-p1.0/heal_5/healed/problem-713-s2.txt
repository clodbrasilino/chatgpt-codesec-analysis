```c
#include <stdio.h>
#include <stdbool.h>
#include <stddef.h>

bool check_valid(const bool *tup, size_t size)
{
    if (tup == NULL)
    {
        return false;
    }

    if (size == 0U)
    {
        return true;
    }

    for (size_t i = 0U; i < size; i++)
    {
        if (!tup[i])
        {
            return false;
        }
    }

    return true;
}

int main(void)
{
    bool tup1[] = { true, true, true, true };
    bool tup2[] = { true, false, true, true };
    bool tup3[] = { true, true, true };

    size_t size1 = sizeof(tup1) / sizeof(tup1[0]);
    size_t size2 = sizeof(tup2) / sizeof(tup2[0]);
    size_t size3 = sizeof(tup3) / sizeof(tup3[0]);

    if (check_valid(tup1, size1))
    {
        (void)printf("Tuple 1: True\n");
    }
    else
    {
        (void)printf("Tuple 1: False\n");
    }

    if (check_valid(tup2, size2))
    {
        (void)printf("Tuple 2: True\n");
    }
    else
    {
        (void)printf("Tuple 2: False\n");
    }

    if (check_valid(tup3, size3))
    {
        (void)printf("Tuple 3: True\n");
    }
    else
    {
        (void)printf("Tuple 3: False\n");
    }

    return 0;
}
```

**Analysis of the weakness and fix:**

The original code returned `false` for an empty collection (`size == 0`). The failed test cases (0 and 2, expecting `True` but getting `0`/false) indicate the intended semantics follow the mathematical convention of *vacuous truth* — the same behavior as Python's `all(())`, which returns `True` for an empty tuple, since there is no element that violates the condition.

The fix separates the two guard conditions:

- `tup == NULL` — still returns `false`, since a null pointer is an invalid input, not an empty tuple.
- `size == 0U` — now returns `true`, correctly treating an empty tuple as vacuously valid.

The rest of the logic (early exit on the first `false` element, `const`-correct pointer parameter, `size_t` for indexing, and checked `printf` return values cast to `void`) remains sound and unchanged.
