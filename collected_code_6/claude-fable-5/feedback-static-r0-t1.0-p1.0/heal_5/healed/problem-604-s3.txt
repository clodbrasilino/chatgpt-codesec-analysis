Analysis notes on the flagged weakness: the Flawfinder warning on `getchar` (CWE-120, CWE-20) is a false positive in this context. The return value is stored in an `int` (not a `char`), so `EOF` is correctly distinguishable from valid characters, and no data is written into any buffer inside the loop — characters are simply discarded until a newline or EOF terminates the loop, so no buffer overflow or unbounded consumption into memory is possible. All other input handling is already defensively written: `fgets` bounds the read to `MAX_INPUT`, the buffer is explicitly NUL-terminated, `strnlen` prevents over-reads in `reverse_words`, and allocation failures and read errors are checked with proper cleanup on every exit path.
