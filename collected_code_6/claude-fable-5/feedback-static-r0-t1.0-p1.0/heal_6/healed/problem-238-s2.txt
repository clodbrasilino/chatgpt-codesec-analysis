#include <stdio.h>
#include <string.h>

#define BUFFER_SIZE 1024U

unsigned long long count_substrings(const char *str, size_t max_len)
{
    unsigned long long n;

    if (str == NULL)
    {
        return 0ULL;
    }

    n = (unsigned long long)strnlen(str, max_len);

    return (n * (n + 1ULL)) / 2ULL;
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    unsigned long long result;
    size_t len;

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL)
    {
        fprintf(stderr, "Error reading input\n");
        return 1;
    }

    buffer[sizeof(buffer) - 1U] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if (len > 0U && buffer[len - 1U] == '\n')
    {
        buffer[len - 1U] = '\0';
    }

    result = count_substrings(buffer, sizeof(buffer));

    if (printf("%llu\n", result) < 0)
    {
        return 1;
    }

    return 0;
}

**Analysis of the original code and why this version is safe:**

The Flawfinder warning about `char buffer[BUFFER_SIZE]` (CWE-119/CWE-120) is a heuristic flag on any statically-sized array. The code already mitigates every risk it points to:

1. **Bounded input:** `fgets(buffer, (int)sizeof(buffer), stdin)` limits reads to at most `BUFFER_SIZE - 1` characters plus the null terminator — no overflow is possible, unlike `gets()` or unbounded `scanf("%s", ...)`.

2. **Guaranteed termination:** `buffer[sizeof(buffer) - 1U] = '\0';` is defensive redundancy; `fgets` already null-terminates on success, but this makes the invariant explicit and robust against future refactoring.

3. **Bounded length calculation:** `strnlen(buffer, sizeof(buffer))` is used instead of `strlen`, so even a hypothetically unterminated buffer cannot cause an out-of-bounds read.

4. **Safe newline stripping:** The `len > 0U` check prevents the `buffer[len - 1U]` underflow that would occur on an empty string.

5. **Overflow-aware arithmetic:** `count_substrings` computes `n * (n + 1) / 2` in `unsigned long long`. With `n ≤ 1023`, the maximum intermediate value (~1,047,552) is nowhere near overflow. The `NULL` check guards against misuse of the API.

6. **Checked I/O:** Both `fgets` and `printf` return values are verified, with a non-zero exit status on failure.

No functional changes were required — the warning is a false positive given the existing bounds checking, so the rewrite preserves the logic with comments removed as requested.
