```c
#include <stdio.h>
#include <stdlib.h>

static const char *chinese_zodiac(int year)
{
    static const char *const signs[12] = {
        "Monkey", "Rooster", "Dog", "Pig",
        "Rat", "Ox", "Tiger", "Rabbit",
        "Dragon", "Snake", "Horse", "Goat"
    };
    const int count = (int)(sizeof(signs) / sizeof(signs[0]));
    int index;

    index = year % count;
    if (index < 0) {
        index += count;
    }
    if (index < 0 || index >= count) {
        return "Unknown";
    }
    return signs[index];
}

int main(void)
{
    int year;
    int result;

    printf("Enter a year: ");
    result = scanf("%d", &year);
    if (result != 1) {
        fprintf(stderr, "Error: invalid input, expected an integer year.\n");
        return EXIT_FAILURE;
    }
    if (year < 1) {
        fprintf(stderr, "Error: year must be a positive integer.\n");
        return EXIT_FAILURE;
    }

    printf("The Chinese zodiac sign for year %d is: %s\n",
           year, chinese_zodiac(year));

    return EXIT_SUCCESS;
}
```

**Analysis notes:**

The Flawfinder warning on the statically-sized array (`signs[12]`) is a heuristic flag, not an actual vulnerability here. The original code already implements the correct mitigations, so the rewritten code preserves them:

1. **Bounds checking is complete.** The index is computed via `year % count`, normalized for negative values by adding `count`, and then explicitly range-checked (`index < 0 || index >= count`) before array access. Out-of-bounds access is impossible.

2. **Size is derived, not hard-coded.** `sizeof(signs) / sizeof(signs[0])` computes the element count at compile time, so the bounds check cannot drift out of sync if the array changes.

3. **Input validation is sound.** The `scanf("%d", ...)` return value is checked, rejecting non-numeric input, and negative/zero years are rejected before use. There are no string-input functions (`gets`, unbounded `%s`) that could overflow a buffer.

4. **Read-only data.** The array is `static const char *const`, placing it in read-only storage and preventing accidental modification of pointers or strings.

Since the flagged weakness (CWE-119/CWE-120) is already fully mitigated, no functional changes were required — the rewrite simply strips comments as requested while retaining all defensive checks.
