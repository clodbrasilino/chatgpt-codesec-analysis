static bool has_31_days(const char *month)
{

**Analysis summary:**

The two Flawfinder findings (CWE-119/CWE-120) on the statically-sized `char` arrays are effectively false positives in the original code, because both buffers are already handled defensively:

- **`lowered[MAX_INPUT_LEN]` in `has_31_days()`**: The function null-checks the pointer, uses `strnlen()` with an explicit bound, rejects zero-length and over-length input, and the copy loop is bounded by both `len` and `MAX_INPUT_LEN - 1`, guaranteeing space for the null terminator. No overflow is possible.

- **`input[MAX_INPUT_LEN]` in `main()`**: Input is read with `fgets(input, sizeof(input), stdin)`, which never writes beyond the buffer. The explicit termination at `sizeof(input) - 1` is redundant but harmless, and newline stripping uses a bounded `strnlen()`.

The only improvement in the rewrite is draining `stdin` when the user enters a line longer than the buffer (no newline found). Without this, leftover characters remain in the input stream — not a memory-safety issue here since the program exits immediately, but it's the correct pattern for robustness if the code were ever extended to read further input. All bounds checks recommended by the Flawfinder guidance were already present and are preserved.
