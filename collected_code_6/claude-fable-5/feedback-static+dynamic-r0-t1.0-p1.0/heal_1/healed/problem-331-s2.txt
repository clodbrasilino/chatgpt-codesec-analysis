```c
#include <stdio.h>
#include <stdlib.h>

unsigned int count_unset_bits(unsigned int number)
{
    unsigned int count = 0U;

    if (number == 0U)
    {
        return 1U;
    }

    while (number > 0U)
    {
        if ((number & 1U) == 0U)
        {
            count++;
        }
        number >>= 1U;
    }

    return count;
}

int main(void)
{
    unsigned int number = 0U;
    unsigned int result = 0U;
    int scan_status = 0;

    printf("Enter a non-negative integer: ");

    scan_status = scanf("%u", &number);
    if (scan_status != 1)
    {
        fprintf(stderr, "Error: invalid input.\n");
        return EXIT_FAILURE;
    }

    result = count_unset_bits(number);

    if (printf("Number of unset bits in %u: %u\n", number, result) < 0)
    {
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
```

**Analysis of the original weakness:** The failing test cases revealed that the original implementation counted unset bits across the *entire* width of `unsigned int` (all 32 bits), including all the leading zeros. For example, an input of `2` (binary `10`) returned `31` because it counted the 30 leading zeros plus the one significant zero, whereas the expected result was `1` — only the unset bit within the significant portion of the number (i.e., up to and including the most significant set bit).

**The fix:** Instead of iterating over a fixed `total_bits` derived from `sizeof(unsigned int) * CHAR_BIT`, the corrected version shifts the number right until it becomes zero, counting only the zero bits encountered up to the highest set bit. This makes the count relative to the number's actual binary representation length. The `number == 0U` edge case returns `1`, treating zero as the single-digit binary value `0`.
