Analysis of the flagged weakness and why the code is safe:

**The `memcpy` finding (CWE-120)** was a false positive in the original code, but the rewrite makes the safety guarantees more explicit:

1. **Bounded length measurement**: `strnlen(src, MAX_INPUT_LEN)` never reads past `MAX_INPUT_LEN` bytes, protecting against unterminated input strings.
2. **Rejection of oversized input**: The `len >= MAX_INPUT_LEN` check ensures `len` is strictly less than the cap before allocation.
3. **Destination sized from the same `len`**: `malloc(len + 1)` guarantees the destination can always hold exactly `len` bytes plus the terminator, so `memcpy(dest, src, len)` cannot overflow — the destination size and copy size derive from the same value.
4. **Explicit zero-length guard**: The added `if (len > 0)` check avoids calling `memcpy` with a zero count, which is harmless but makes intent clearer to static analyzers.
5. **Guaranteed NUL termination**: `dest[len] = '\0'` is always written within bounds.

Other defensive properties preserved from the original:
- **Overflow-checked reallocation** (`capacity > SIZE_MAX / (2 * sizeof(char *))`) prevents integer overflow in the `realloc` size computation.
- **Complete cleanup on every error path** — no memory leaks on allocation failure.
- **`strtok_r` instead of `strtok`** for reentrancy.
- **`tolower((unsigned char)...)`** avoids undefined behavior with negative `char` values.
