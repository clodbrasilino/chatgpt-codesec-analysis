## Analysis

The flagged weakness is the call to `strlen(str)` (CWE-126, buffer over-read): `strlen` scans until it finds a `'\0'`, so if the caller passes a buffer that is not NUL-terminated, the function reads past the end of the allocation. Everything that follows (`len`, the allocation size, and the copy loop) is then driven by that out-of-bounds value.

**Fix applied:**
- Replaced `strlen` with a bounded length computation that never reads more than `max_len` bytes (equivalent to `strnlen`, written manually for full portability — no POSIX feature-test macros required).
- Added a `max_len` parameter to `string_to_tuple` so the bound is explicit and controlled by the caller.
- A string that is not NUL-terminated within `max_len` is now rejected (`return -1`) instead of causing an over-read. An empty (but properly terminated) string still returns success with an empty tuple.
- The rest of the logic (rollback on partial allocation failure, `free_tuple`, `print_tuple`) was already sound and is kept intact.

## Rewritten code

```c
#include <stdio.h>
#include <stdlib.h>

#define MAX_STRING_LENGTH 4096

typedef struct {
    char **items;
    size_t size;
} Tuple;

static size_t bounded_strnlen(const char *s, size_t max_len)
{
    size_t i;

    for (i = 0; i < max_len; i++) {
        if (s[i] == '\0') {
            break;
        }
    }

    return i;
}

int string_to_tuple(const char *str, size_t max_len, Tuple *tuple)
{
    size_t len;
    size_t i;

    if (str == NULL || tuple == NULL || max_len == 0) {
        return -1;
    }

    tuple->items = NULL;
    tuple->size = 0;

    len = bounded_strnlen(str, max_len);

    if (len == max_len) {
        return -1;
    }

    if (len == 0) {
        return 0;
    }

    tuple->items = malloc(len * sizeof(*tuple->items));
    if (tuple->items == NULL) {
        return -1;
    }

    for (i = 0; i < len; i++) {
        tuple->items[i] = malloc(2 * sizeof(**tuple->items));
        if (tuple->items[i] == NULL) {
            while (i > 0) {
                free(tuple->items[--i]);
            }
            free(tuple->items);
            tuple->items = NULL;
            return -1;
        }
        tuple->items[i][0] = str[i];
        tuple->items[i][1] = '\0';
    }

    tuple->size = len;
    return 0;
}

void free_tuple(Tuple *tuple)
{
    size_t i;

    if (tuple == NULL) {
        return;
    }

    for (i = 0; i < tuple->size; i++) {
        free(tuple->items[i]);
    }
    free(tuple->items);
    tuple->items = NULL;
    tuple->size = 0;
}

void print_tuple(const Tuple *tuple)
{
    size_t i;

    if (tuple == NULL) {
        return;
    }

    printf("(");
    for (i = 0; i < tuple->size; i++) {
        printf("'%s'", tuple->items[i]);
        if (i + 1 < tuple->size) {
            printf(", ");
        }
    }
    printf(")\n");
}

int main(void)
{
    const char *str = "hello";
    Tuple tuple;

    if (string_to_tuple(str, MAX_STRING_LENGTH, &tuple) != 0) {
        fprintf(stderr, "Error: failed to convert string to tuple\n");
        return EXIT_FAILURE;
    }

    print_tuple(&tuple);

    free_tuple(&tuple);

    return EXIT_SUCCESS;
}
```

**Key behavioral change:** the scan in `bounded_strnlen` touches at most `max_len` bytes regardless of whether the buffer contains a terminator, so the over-read is eliminated. Note that since `len` is now bounded by the caller-supplied `max_len`, the allocation `len * sizeof(*tuple->items)` is also protected against wrap-around as long as callers pass a sane bound (as `main` does with `MAX_STRING_LENGTH`).
