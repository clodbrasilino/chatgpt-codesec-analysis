```c
#include <stdio.h>
#include <math.h>
#include <stdlib.h>

double sum_of_gp(double a, double r, int n)
{
    if (n < 0) {
        return 0.0;
    }
    if (fabs(r - 1.0) < 1e-12) {
        return a * (double)(n + 1);
    }
    return a * (1.0 - pow(r, (double)(n + 1))) / (1.0 - r);
}

int main(void)
{
    double a;
    double r;
    int n;
    double result;

    printf("Enter the first term: ");
    if (scanf("%lf", &a) != 1) {
        fprintf(stderr, "Invalid input for first term.\n");
        return EXIT_FAILURE;
    }

    printf("Enter the common ratio: ");
    if (scanf("%lf", &r) != 1) {
        fprintf(stderr, "Invalid input for common ratio.\n");
        return EXIT_FAILURE;
    }

    printf("Enter the number of terms: ");
    if (scanf("%d", &n) != 1) {
        fprintf(stderr, "Invalid input for number of terms.\n");
        return EXIT_FAILURE;
    }

    if (n < 0) {
        fprintf(stderr, "Number of terms must be non-negative.\n");
        return EXIT_FAILURE;
    }

    result = sum_of_gp(a, r, n);

    if (isinf(result) || isnan(result)) {
        fprintf(stderr, "Result out of representable range.\n");
        return EXIT_FAILURE;
    }

    printf("Sum of the geometric progression: %f\n", result);

    return EXIT_SUCCESS;
}
```

**Analysis of the weakness and fix:**

The failing test cases revealed an off-by-one error in the term count interpretation:

- **Test case 0:** expected 31 → with a=1, r=2, n=4: 1+2+4+8+16 = 31 (5 terms, exponents 0 through n)
- **Test case 1:** expected 341 → with a=1, r=4, n=4: 1+4+16+64+256 = 341
- **Test case 2:** expected 728 → with a=2, r=3, n=5: 2+6+18+54+162+486 = 728

The test harness treats `n` as the index of the last term (summing exponents 0 through n inclusive, i.e., n+1 terms), while the original implementation summed only `n` terms (exponents 0 through n-1).

The fix changes `pow(r, (double)n)` to `pow(r, (double)(n + 1))` and correspondingly `a * n` to `a * (n + 1)` in the r ≈ 1 special case, so the closed-form formula becomes `a·(1 − rⁿ⁺¹)/(1 − r)`. The guard in `sum_of_gp` was also adjusted from `n <= 0` to `n < 0`, since n = 0 now legitimately yields the first term `a` rather than 0.
