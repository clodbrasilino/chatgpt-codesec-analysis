```c
#include <stdio.h>
#include <stddef.h>

#define BUFFER_SIZE 256

size_t string_length(const char *str)
{
    size_t length = 0;

    if (str == NULL) {
        return 0;
    }

    while (str[length] != '\0') {
        length++;
    }

    return length;
}

int main(int argc, const char *argv[])
{
    char buffer[BUFFER_SIZE];
    size_t length;
    size_t i;

    if (argc > 1 && argv[1] != NULL) {
        length = string_length(argv[1]);
        printf("%zu\n", length);
        fflush(stdout);
        return 0;
    }

    if (fgets(buffer, (int)sizeof(buffer), stdin) == NULL) {
        printf("0\n");
        fflush(stdout);
        return 0;
    }

    buffer[sizeof(buffer) - 1] = '\0';

    i = 0;
    while (i < sizeof(buffer) && buffer[i] != '\0') {
        if (buffer[i] == '\n') {
            buffer[i] = '\0';
            break;
        }
        i++;
    }

    length = string_length(buffer);

    printf("%zu\n", length);
    fflush(stdout);

    return 0;
}
```

**Analysis notes:**

The Flawfinder warning (CWE-119/CWE-120) on the statically-sized `char buffer[BUFFER_SIZE]` is a low-risk, informational flag rather than an actual vulnerability in this code. The original source already implements all the necessary mitigations, so the rewritten code is functionally identical with comments removed:

1. **Bounded input:** `fgets(buffer, (int)sizeof(buffer), stdin)` limits reads to at most `BUFFER_SIZE - 1` characters plus the null terminator, preventing buffer overflow on input.

2. **Guaranteed termination:** `buffer[sizeof(buffer) - 1] = '\0';` is defensive redundancy — `fgets` already null-terminates, but this guards against any edge case.

3. **Bounds-checked iteration:** The newline-stripping loop checks `i < sizeof(buffer)` before dereferencing, so it can never read past the array.

4. **NULL-safe helper:** `string_length()` guards against a `NULL` pointer before iterating, and only reads up to the first `'\0'`, which is guaranteed to exist within the buffer.

5. **Safe format usage:** `printf` uses a constant format string with `%zu` correctly matching `size_t`, avoiding format-string vulnerabilities and type mismatches.

The only theoretical residual concern is that `argv[1]` could be a very long string, but `string_length` only reads it (never copies it into the fixed buffer), so no overflow is possible. The code is safe as written.
