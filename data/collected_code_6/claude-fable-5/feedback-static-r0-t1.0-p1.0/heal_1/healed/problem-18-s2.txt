#include <stdio.h>
#include <string.h>
#include <limits.h>

void remove_chars(char *first, const char *second)
{
    int present[UCHAR_MAX + 1] = {0};
    size_t i;
    size_t j;

    if (first == NULL || second == NULL) {
        return;
    }

    for (i = 0; second[i] != '\0'; i++) {
        present[(unsigned char)second[i]] = 1;
    }

    j = 0;
    for (i = 0; first[i] != '\0'; i++) {
        if (!present[(unsigned char)first[i]]) {
            first[j] = first[i];
            j++;
        }
    }
    first[j] = '\0';
}

int main(void)
{
    char first[256];
    char second[256];

    if (fgets(first, sizeof(first), stdin) == NULL) {
        fprintf(stderr, "Failed to read first string\n");
        return 1;
    }
    first[strcspn(first, "\n")] = '\0';

    if (fgets(second, sizeof(second), stdin) == NULL) {
        fprintf(stderr, "Failed to read second string\n");
        return 1;
    }
    second[strcspn(second, "\n")] = '\0';

    remove_chars(first, second);

    if (printf("%s\n", first) < 0) {
        return 1;
    }

    return 0;
}

**CWE-119/CWE-120 (buffer overflow on `first[256]` and `second[256]`):** These are Flawfinder false positives triggered by the mere presence of statically-sized arrays. The code already implements the recommended mitigations:

1. **Bounded input:** Both reads use `fgets(buf, sizeof(buf), stdin)`, which limits input to `sizeof(buf) - 1` characters plus the null terminator. No overflow is possible, unlike `gets()` or unbounded `scanf("%s", ...)`.

2. **Safe newline stripping:** `buf[strcspn(buf, "\n")] = '\0'` is the idiomatic, safe pattern — `strcspn` always returns an index within the null-terminated string, so the write is in-bounds even when no newline is present (e.g., on truncated input or EOF without newline).

3. **Return-value checking:** Both `fgets` calls and the `printf` call are checked for failure, handling EOF and I/O errors gracefully.

4. **Safe indexing in `remove_chars`:** The lookup table is indexed via `(unsigned char)` casts, preventing negative-index undefined behavior on platforms where `char` is signed, and the table is sized `UCHAR_MAX + 1` to cover all byte values. `first[j] = '\0'` is always in-bounds since `j <= i` and `first[i]` was a valid read.

5. **NULL guards:** `remove_chars` defensively checks both pointers.
