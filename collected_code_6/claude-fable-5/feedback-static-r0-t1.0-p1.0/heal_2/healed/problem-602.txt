```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdbool.h>

#define BUFFER_SIZE 256

int first_repeated_char(const char *str)
{
    bool seen[256] = { false };
    size_t i;

    if (str == NULL) {
        return -1;
    }

    for (i = 0; str[i] != '\0'; i++) {
        unsigned char c = (unsigned char)str[i];
        if (seen[c]) {
            return (int)c;
        }
        seen[c] = true;
    }

    return -1;
}

int main(void)
{
    char buffer[BUFFER_SIZE];
    int result;

    printf("Enter a string: ");
    if (fgets(buffer, sizeof(buffer), stdin) == NULL) {
        fprintf(stderr, "Error reading input\n");
        return EXIT_FAILURE;
    }

    buffer[sizeof(buffer) - 1] = '\0';
    buffer[strcspn(buffer, "\n")] = '\0';

    result = first_repeated_char(buffer);

    if (result == -1) {
        printf("No repeated character found\n");
    } else {
        printf("First repeated character: %c\n", (char)result);
    }

    return EXIT_SUCCESS;
}
```

**Analysis notes:**

The original code was already well-hardened against the Flawfinder-identified weakness (CWE-119/CWE-120, statically-sized buffer). Here's why the code is safe as written:

1. **Bounded input**: `fgets(buffer, sizeof(buffer), stdin)` reads at most `sizeof(buffer) - 1` characters and always null-terminates within bounds — this is the correct, length-limited alternative to unsafe functions like `gets()` or unbounded `scanf("%s", ...)`.

2. **Defensive null-termination**: `buffer[sizeof(buffer) - 1] = '\0';` is technically redundant after `fgets` (which guarantees termination), but it costs nothing and protects against future refactoring mistakes.

3. **Safe newline stripping**: `strcspn(buffer, "\n")` returns an index that is always within the string (at worst the position of the terminating null), so the assignment cannot write out of bounds — unlike the common buggy idiom `buffer[strlen(buffer) - 1] = '\0'`, which underflows on an empty string.

4. **Safe array indexing in `first_repeated_char`**: casting to `unsigned char` before indexing `seen[256]` prevents negative-index undefined behavior on platforms where plain `char` is signed and the input contains bytes ≥ 0x80.

5. **NULL check** on the input pointer guards against misuse of the API.

6. **Return-value checking** of `fgets` handles EOF/read errors instead of processing an indeterminate buffer.

The Flawfinder hit is a risk-level-2 informational finding triggered simply by the presence of a fixed-size `char` array; the existing bounds-checked usage already satisfies the recommended mitigation, so no functional changes were required.
