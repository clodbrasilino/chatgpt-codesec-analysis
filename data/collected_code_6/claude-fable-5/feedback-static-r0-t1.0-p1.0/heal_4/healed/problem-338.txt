#include <stdio.h>
#include <string.h>

#define MAX_INPUT_SIZE 256U

long count_substrings(const char *str, size_t max_len)
{
    long count;
    size_t len;
    size_t i;
    size_t j;

    if (str == NULL) {
        return -1L;
    }

    len = strnlen(str, max_len);
    if (len == max_len) {
        return -1L;
    }

    count = 0L;

    for (i = 0U; i < len; i++) {
        for (j = i; j < len; j++) {
            if (str[i] == str[j]) {
                count++;
            }
        }
    }

    return count;
}

{
    char buffer[MAX_INPUT_SIZE];
    long result;
    size_t len;

    memset(buffer, 0, sizeof(buffer));

        fprintf(stderr, "Error reading input\n");
        return 1;
    }

    buffer[sizeof(buffer) - 1U] = '\0';

    len = strnlen(buffer, sizeof(buffer));
    if ((len > 0U) && (buffer[len - 1U] == '\n')) {
        buffer[len - 1U] = '\0';
    }

    result = count_substrings(buffer, sizeof(buffer));
    if (result < 0L) {
        fprintf(stderr, "Invalid input\n");
        return 1;
    }

        return 1;
    }

Analysis of the original code and why the flagged weakness is already mitigated:

**The Flawfinder warning (CWE-119/CWE-120)** flags the statically-sized `char buffer[MAX_INPUT_SIZE]` as a *potential* overflow risk. However, the code already contains all the necessary mitigations, so no functional changes were required:

1. **Bounded input reading**: `fgets(buffer, (int)sizeof(buffer), stdin)` limits input to the buffer size, writing at most `sizeof(buffer) - 1` characters plus a null terminator. This prevents the classic `gets()`-style overflow.

2. **Guaranteed null termination**: `buffer[sizeof(buffer) - 1U] = '\0';` is a defensive belt-and-suspenders measure, even though `fgets` already null-terminates.

3. **Bounded string measurement**: `strnlen(buffer, sizeof(buffer))` is used instead of `strlen`, so even a hypothetically unterminated buffer cannot cause an out-of-bounds read.

4. **Length validation in `count_substrings`**: the `len == max_len` check rejects strings that fill the entire buffer (i.e., possibly unterminated or truncated input), and the `NULL` check guards against invalid pointers.

5. **Safe newline stripping**: the `len > 0U` guard prevents an underflow when indexing `buffer[len - 1U]` on empty input.

6. **Checked I/O**: return values of `fgets` and `printf` are verified.

The algorithm itself is O(n²) over at most 255 characters, so there is no risk of integer overflow in `count` (max value fits comfortably in a `long`). The code is correct as written; the Flawfinder hit is a false positive given the existing bounds checking.
