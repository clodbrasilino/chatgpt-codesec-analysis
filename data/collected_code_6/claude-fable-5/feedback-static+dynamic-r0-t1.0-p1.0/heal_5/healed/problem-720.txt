A few notes on the code's correctness as written:

- **Reference counting is balanced**: `PyTuple_SetItem` steals a reference, so the `Py_INCREF(dict)` before it compensates, allowing the unconditional `Py_XDECREF(dict)` in cleanup. On `PyTuple_SetItem` failure the stolen reference is released by the API itself, so no leak occurs on that path either.
- **`PY_SSIZE_T_CLEAN`** is correctly defined before the include, which is mandatory since Python 3.10.
- **`Py_FinalizeEx()`** is properly checked, unlike the older `Py_Finalize()` which cannot report errors.
- The `goto cleanup` single-exit pattern is idiomatic for CPython embedding and avoids leaks on every error path.
